# Command Reference

All root commands are run as `task <name>` unless noted otherwise.

The Docker tasks are the supported way to run LAREX locally and in production. Native install/build tasks are for maintainers who run individual services outside Docker or who need local checks before committing.

## Common Task Commands

| Command | Description |
|---------|-------------|
| `task setup` | Optional native-helper setup: installs JavaScript dependencies and starts Docker infrastructure |
| `task install` | Optional native-helper install for docs, frontend, and Keycloak theme dependencies |
| `task dev` | Prints the hybrid native startup flow and points to `task docker:up` for all-Docker development |
| `task test` | Run backend, frontend, and docs checks on the host |
| `task build` | Build backend, docs, frontend, and theme on the host |
| `task clean` | Remove build artifacts |

## Docker Tasks

### Local dev

| Command | Description |
|---------|-------------|
| `task docker:up` | Start the supported local Docker development stack |
| `task docker:up:build` | Rebuild and start the local dev stack |
| `task docker:up:docs` | Start local dev stack with self-hosted docs |
| `task docker:down` | Stop the local dev stack |
| `task docker:down:docs` | Stop local dev stack with docs override |
| `task docker:down:clean` | Stop the local dev stack and remove volumes |
| `task docker:infra` | Start only shared infrastructure for optional native service development |
| `task docker:logs` | View local dev logs |
| `task docker:logs:backend` | View backend logs |
| `task docker:logs:frontend` | View frontend logs |
| `task docker:logs:docs` | View docs logs in local dev stack |
| `task docker:ps` | Show local dev containers |

### Production-like and production

| Command | Description |

| `task docker:prod:init-env` | Create `.env.prod` from the template and seed required secrets |
| `task docker:prod:up` | Start the opinionated production stack |

| `task docker:prod:up:kraken` | Start opinionated production with bundled Kraken segmentation |
| `task docker:prod:down` | Stop the opinionated production stack |
| `task docker:prod:down:docs` | Stop opinionated production with docs override |
| `task docker:prod:down:kraken` | Stop opinionated production with bundled Kraken segmentation |
| `task docker:prod:logs` | View opinionated production logs |
| `task docker:prod:logs:docs` | View docs logs in opinionated production |
| `task docker:prod:logs:kraken` | View bundled Kraken logs in opinionated production |
| `task docker:prod:local:init-env` | Create `.env.prod.local` from the template and seed required secrets |
| `task docker:prod:local:up` | Start local production-like services |
| `task docker:prod:local:up:docs` | Start local production-like services with docs |
| `task docker:prod:local:up:kraken` | Start local production-like services with bundled Kraken segmentation |
| `task docker:prod:local:down` | Stop local production-like services |
| `task docker:prod:local:down:docs` | Stop local production-like services with docs |
| `task docker:prod:local:down:kraken` | Stop local production-like services with bundled Kraken segmentation |

## Direct Docker Compose Commands

Use direct Docker Compose commands when Taskfile is not installed. They are equivalent to the Taskfile shortcuts.

### Local dev

```bash
docker compose up -d
docker compose logs -f
docker compose down
```

With self-hosted docs:

```bash
docker compose -f compose.yaml -f compose.dev.docs.yaml up -d
```

### Local production-like

```bash
docker compose --env-file .env.prod.local \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.local.yaml \
  up -d
```

With self-hosted docs:

```bash
docker compose --env-file .env.prod.local \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.local.yaml \
  -f compose.prod.local.docs.yaml \
  up -d
```

### Opinionated production

```bash
docker compose --env-file .env.prod \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.publish.localhost.yaml \
  up -d
```

With self-hosted docs:

```bash
docker compose --env-file .env.prod \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.publish.localhost.yaml \
  -f compose.prod.docs.yaml \
  up -d
```

### Production with external Keycloak

```bash
docker compose --env-file .env.prod \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.external-keycloak.yaml \
  -f compose.prod.publish.localhost.yaml \
  up -d
```
