# Docker Development

Docker is the supported development environment for LAREX. The development compose stack builds local images from the repository, mounts source code where hot reload is useful, and starts the shared services needed by the application.

You do not need Java, Node.js, pnpm, or PostgreSQL on the host for the full Docker workflow. Those tools are only needed for [Native Service Development](/development/local-setup).

## Development Modes

| Mode | Command | What runs in Docker | Use it when |
| --- | --- | --- | --- |
| Full dev stack | `task docker:up` | Everything in `compose.yaml` | You want the supported all-container workflow |
| Rebuild full dev stack | `task docker:up:build` | Everything, after rebuilding images | Dockerfiles or dependencies changed |
| Infrastructure only | `task docker:infra` | PostgreSQL, Keycloak, Traefik | You run backend/frontend natively |
| Full dev stack with docs | `task docker:up:docs` | Default stack plus docs | You also want `docs.localhost` |
| Full dev stack with official Actions | `task docker:actions:up` | Default stack plus all official processor profiles | You are developing or testing processor workflows |

## Full Docker Workflow

Start the stack:

```bash
task docker:up
```

Open:

- `http://larex.localhost`
- `http://keycloak.localhost`
- `http://mail.localhost`
- `http://mock-action-processor.localhost`

View status and logs:

```bash
task docker:ps
task docker:logs
```

Stop the stack:

```bash
task docker:down
```

Delete local volumes as well:

```bash
task docker:down:clean
```

`docker:down:clean` removes local PostgreSQL and Keycloak data. Use it only when you want a fresh local state.

## Include The Docs App

```bash
task docker:up:docs
```

This adds `compose.dev.docs.yaml` and exposes:

- `http://docs.localhost`

Stop the docs-enabled stack with:

```bash
task docker:down:docs
```

## Include Official Action Processors

```bash
task docker:actions:up
```

This uses the optional `compose.actions.yaml` fragment and its `actions` profile.
Processor secrets and image pins live in `.env.actions`, independently from the
core development environment. See [Official Action Services](/development/official-action-services).

## Infrastructure-Only Workflow

Use this when you explicitly want to run one service on the host:

```bash
task docker:infra
```

This starts only:

- `postgres`
- `keycloak`
- `traefik`

Then run the service you are editing with native tooling, for example:

```bash
task backend:dev
task frontend:dev
```

This hybrid mode is useful for IDE debugging, but the full Docker stack remains the default supported workflow.

## What `compose.yaml` Contains

| Service | Development responsibility |
| --- | --- |
| `socket-proxy` | Gives Traefik limited Docker socket access |
| `traefik` | Routes `*.localhost` hostnames |
| `postgres` | Application database |
| `keycloak-postgres` | Keycloak database |
| `keycloak` | Local auth realm and theme |
| `mailpit` | Local email inbox |
| `app` | Spring Boot backend built from `backend/Dockerfile` |
| `frontend` | Nuxt frontend built from `frontend/Dockerfile` |
| `mock-action-processor` | Example processor for LAREX Actions |

Official processors such as Kraken are intentionally absent from `compose.yaml`.
They are added by `compose.actions.yaml`, keeping heavyweight processor workloads
optional while sharing the same private backend network.

The development backend image mounts `backend/src`, Gradle build files, and upload storage. The frontend image mounts the frontend source tree and keeps `node_modules` inside the container.

## Local Routes And Ports

| Route or port | Service |
| --- | --- |
| `http://larex.localhost` | frontend |
| `http://api.localhost` | backend API |
| `http://keycloak.localhost` | Keycloak |
| `http://mail.localhost` | Mailpit |
| `http://mock-action-processor.localhost` | mock Action processor |
| `localhost:5432` | application PostgreSQL |
| `localhost:8080` | backend direct port |
| `localhost:5005` | backend debug port |
| `localhost:3000` | frontend direct port |

Prefer the routed `*.localhost` URLs in the browser because the local Keycloak realm is configured for those hostnames.

## SELinux Hosts

On SELinux-enabled hosts such as Fedora, RHEL, and CentOS, bind mounts must be relabeled. The committed compose files already use `:Z` or `,Z` for private single-container bind mounts.

Keep those labels when customizing the compose files. Use `:z` only when the same host path is intentionally shared by multiple containers.

## Useful Commands

```bash
task docker:logs:backend
task docker:logs:frontend
task docker:logs:docs
task status
```

Direct Docker Compose equivalents:

```bash
docker compose -f compose.yaml ps
docker compose -f compose.yaml logs -f
docker compose -f compose.yaml up -d --build
```

## Common Issues

| Symptom | Check |
| --- | --- |
| A route does not load | Confirm Traefik is running and no other process owns port `80`. |
| Login fails after switching modes | Use `http://larex.localhost`, not a raw `localhost` frontend URL, unless you also update Keycloak redirects. |
| Backend changes do not reload | Rebuild with `task docker:up:build` after dependency or build-file changes. Source changes under `backend/src` are mounted. |
| Frontend dependencies changed | Rebuild the frontend container with `task docker:up:build`. |
| Local data is inconsistent | Stop with `task docker:down:clean` and start again, accepting data loss. |
