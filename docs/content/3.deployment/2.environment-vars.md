# Environment Variables

LAREX now ships two committed env examples:

- `deployment/env/.env.prod.example`
- `deployment/env/.env.prod.local.example`

The production env file is the canonical example. The local production-like env file is intentionally smaller and relies on local defaults.

## Primary Production Variables

These are the values operators normally edit.

| Variable | Purpose |
|----------|---------|
| `LAREX_PUBLIC_HOST` | Public frontend hostname |
| `KEYCLOAK_PUBLIC_HOST` | Public Keycloak hostname |
| `KEYCLOAK_REALM` | Keycloak realm name |
| `LAREX_BIND_IP` | Host interface for published ports |
| `POSTGRES_USER` | Database username |
| `POSTGRES_PASSWORD` | Database password |
| `KEYCLOAK_ADMIN` | Bundled Keycloak bootstrap admin username |
| `KEYCLOAK_ADMIN_PASSWORD` | Bundled Keycloak bootstrap admin password |
| `KEYCLOAK_ADMIN_CLIENT_SECRET` | Backend service-account secret |
| `NUXT_SESSION_PASSWORD` | Nuxt session secret |
| `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET` | Frontend OAuth client secret |
| `LAREX_INITIAL_ADMIN_*` | Initial seeded admin account details |
| `LAREX_USER_PROVISIONING_MODE` | `LOCAL` or `LDAP_MANAGED` |
| `MAIL_*` | SMTP configuration |

## Derived Values

The compose files derive these from the primary variables unless you override them explicitly:

- frontend OAuth redirect URL
- frontend public Keycloak URL
- backend issuer URL
- backend JWK URL for bundled Keycloak
- CORS allowed origin
- bundled Keycloak frontend URL

That keeps the public env contract small and avoids making operators hand-edit several nearly identical URLs.

## Local Production-Like Variables

`deployment/env/.env.prod.local.example` usually only needs:

- `NUXT_SESSION_PASSWORD`
- `KEYCLOAK_ADMIN_CLIENT_SECRET`
- `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET`

Optional local overrides include:

- `KEYCLOAK_REALM`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `KEYCLOAK_ADMIN`
- `KEYCLOAK_ADMIN_PASSWORD`
- `LAREX_INITIAL_ADMIN_*`

## External Keycloak

When using `compose.prod.auth.external-keycloak.yaml`, you still use `.env.prod`, but the important values become:

- `KEYCLOAK_PUBLIC_HOST`
- `KEYCLOAK_REALM`
- `KEYCLOAK_ADMIN_CLIENT_SECRET`
- `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET`

If your external Keycloak needs different server-side URLs than the public hostname, use explicit advanced overrides:

- `KEYCLOAK_ADMIN_SERVER_URL`
- `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_ISSUER_URI`
- `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWK_SET_URI`
- `NUXT_OAUTH_KEYCLOAK_SERVER_URL`
- `NUXT_OAUTH_KEYCLOAK_SERVER_URL_INTERNAL`
- `NUXT_OAUTH_KEYCLOAK_REDIRECT_URL`

## Optional Bundled Nginx

`compose.prod.nginx.yaml` uses:

- `LAREX_PUBLIC_HOST`
- `KEYCLOAK_PUBLIC_HOST`
- `NGINX_CERTS_DIR`
- optional `KEYCLOAK_UPSTREAM`

Keep `KEYCLOAK_UPSTREAM=http://keycloak:8080` for bundled Keycloak. When combining Nginx with external Keycloak, set `KEYCLOAK_UPSTREAM` to the external auth URL.

It expects certificate files named after the public hosts:

- `${LAREX_PUBLIC_HOST}.crt` / `${LAREX_PUBLIC_HOST}.key`
- `${KEYCLOAK_PUBLIC_HOST}.crt` / `${KEYCLOAK_PUBLIC_HOST}.key`

## Security Notes

Do not commit populated `.env.prod` files. At minimum, protect:

- `POSTGRES_PASSWORD`
- `KEYCLOAK_ADMIN_PASSWORD`
- `KEYCLOAK_ADMIN_CLIENT_SECRET`
- `LAREX_INITIAL_ADMIN_TEMP_PASSWORD`
- `NUXT_SESSION_PASSWORD`
- `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET`
- `MAIL_PASSWORD`

## Validation

```bash
docker compose -f compose.yaml config

docker compose --env-file deployment/env/.env.prod.local.example \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.local.yaml \
  config

docker compose --env-file deployment/env/.env.prod.example \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.publish.localhost.yaml \
  config
```
