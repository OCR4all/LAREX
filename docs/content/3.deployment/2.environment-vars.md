# Environment Variables

LAREX now ships two committed env examples:

- `deployment/env/.env.prod.example`
- `deployment/env/.env.prod.local.example`

The production env file is the canonical example. The local production-like env file is intentionally smaller and relies on local defaults.

Production `up`, `pull`, `upgrade`, and config-validation tasks initialize the
relevant env file idempotently before use. Known template placeholders are replaced
with generated secrets, while existing operator values are preserved.

## Primary Production Variables

These are the values operators normally edit.

| Variable | Purpose |
|----------|---------|
| `LAREX_INSTANCE_NAME` | Stable, human-readable deployment name used for UI metadata, email naming, and client-side storage isolation |
| `NUXT_PUBLIC_DOCUMENTATION_URL` | Documentation link shown in the frontend; defaults to `https://docs.larex.kallimachos.de` and can point to self-hosted docs |
| `LAREX_PUBLIC_HOST` | Public frontend hostname |
| `KEYCLOAK_PUBLIC_HOST` | Public Keycloak hostname |
| `KEYCLOAK_REALM` | Keycloak realm name |
| `LAREX_BIND_IP` | Host interface for published ports |
| `LAREX_IMAGE_TAG` | Backend/frontend/docs image tag to deploy from GHCR |
| `LAREX_BACKEND_IMAGE` | Optional full backend image override |
| `LAREX_FRONTEND_IMAGE` | Optional full frontend image override |
| `LAREX_DOCS_IMAGE` | Optional full self-hosted documentation image override |
| `POSTGRES_USER` | Database username |
| `POSTGRES_PASSWORD` | Database password |
| `KEYCLOAK_ADMIN` | Bundled Keycloak bootstrap admin username |
| `KEYCLOAK_ADMIN_PASSWORD` | Bundled Keycloak bootstrap admin password |
| `KEYCLOAK_ADMIN_CLIENT_SECRET` | Backend service-account secret |
| `NUXT_SESSION_PASSWORD` | Nuxt session secret |
| `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET` | Frontend OAuth client secret |
| `LAREX_INITIAL_ADMIN_*` | Initial seeded admin account details |
| `LAREX_USER_PROVISIONING_MODE` | `LOCAL` or `LDAP_MANAGED` |
| `MAIL_*` | SMTP configuration |
| `LAREX_ACTIONS_PUBLIC_BASE_URL` | Optional public backend API base URL used in Action dispatch payloads |
| `LAREX_ACTIONS_ENDPOINT_ALLOWED_ORIGINS` | Optional comma-separated allowlist for Action processor endpoint origins |
| `LAREX_ACTION_ENDPOINT_SECRET_ENCRYPTION_KEY` | Server-side key used to encrypt admin-managed Action endpoint secrets |
| `LAREX_ACTION_ENDPOINT_SECRET_<REF>` | Optional fallback shared HMAC secret used to sign LAREX Action dispatch calls |
| `LAREX_ACTION_RESULT_MAX_FILE_BYTES` | Maximum individual Action result file and Spring multipart file size; defaults to 100 MiB |
| `LAREX_ACTION_OUTPUT_SHARE_PUBLIC_BASE_URL` | Optional public base URL used in newly created Action-output share links; defaults to the configured browser origin plus `/api/public/action-outputs` |
| `LAREX_ACTION_RESULT_MAX_TOTAL_BYTES` | Maximum aggregate Action callback and Spring multipart request size; defaults to 480 MiB |
| `LAREX_DISPATCH_HMAC_SECRET` | Typical processor-side env var for the same shared HMAC secret |

## Derived Values

The compose files derive these from the primary variables unless you override them explicitly:

- frontend OAuth redirect URL
- frontend public Keycloak URL
- backend issuer URL
- backend JWK URL for bundled Keycloak
- CORS allowed origin
- bundled Keycloak frontend URL

That keeps the public env contract small and avoids making operators hand-edit several nearly identical URLs.

## Image Selection

Production Compose defaults to:

- `ghcr.io/ocr4all/larex/backend:${LAREX_IMAGE_TAG:-latest}`
- `ghcr.io/ocr4all/larex/frontend:${LAREX_IMAGE_TAG:-latest}`
- `ghcr.io/ocr4all/larex/docs:${LAREX_IMAGE_TAG:-latest}` when self-hosted docs are selected

Set `LAREX_IMAGE_TAG` to a released version for reproducible production deployments. For non-production environments, use a branch tag such as `dev` or `staging`; builds from `next` also publish the snapshot version stored in `VERSION` (currently `1.0.0-SNAPSHOT`). Use the full image overrides only when deploying images from a fork, mirror, or private registry.

Production start and upgrade tasks wait up to 300 seconds for service health. Set
the shell variable `LAREX_COMPOSE_WAIT_TIMEOUT` when a slower host needs a longer
startup window; this is an orchestration setting and does not need to be stored in
the container env file.

## Local Production-Like Variables

`deployment/env/.env.prod.local.example` usually only needs:

- `NUXT_SESSION_PASSWORD`
- `KEYCLOAK_ADMIN_CLIENT_SECRET`
- `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET`

Optional local overrides include:

- `LAREX_INSTANCE_NAME`
- `NUXT_PUBLIC_DOCUMENTATION_URL`
- `KEYCLOAK_REALM`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `KEYCLOAK_POSTGRES_USER`
- `KEYCLOAK_POSTGRES_PASSWORD`
- `KEYCLOAK_ADMIN`
- `KEYCLOAK_ADMIN_PASSWORD`
- `LAREX_INITIAL_ADMIN_*`

## External Keycloak

When using `compose.prod.auth.external-keycloak.yaml`, you still use `.env.prod`, but the important values become:

- `KEYCLOAK_PUBLIC_HOST`
- `KEYCLOAK_REALM`
- `KEYCLOAK_ADMIN_CLIENT_SECRET`
- `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET`

If your external Keycloak needs different server-side URLs than the public hostname, use explicit advanced overrides:

- `KEYCLOAK_ADMIN_SERVER_URL`
- `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_ISSUER_URI`
- `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWK_SET_URI`
- `NUXT_OAUTH_KEYCLOAK_SERVER_URL`
- `NUXT_OAUTH_KEYCLOAK_SERVER_URL_INTERNAL`
- `NUXT_OAUTH_KEYCLOAK_REDIRECT_URL`

## Optional Bundled Nginx

`compose.prod.nginx.yaml` uses:

- `LAREX_PUBLIC_HOST`
- `KEYCLOAK_PUBLIC_HOST`
- `NGINX_CERTS_DIR`
- optional `NGINX_TEMPLATE_FILE`
- optional `KEYCLOAK_UPSTREAM` for the bundled-Keycloak template

Keep the default template and `KEYCLOAK_UPSTREAM=http://keycloak:8080` for bundled Keycloak. With external Keycloak, set `NGINX_TEMPLATE_FILE=./deployment/nginx/templates/larex-proxy.external-keycloak.conf.template`; this template exposes only LAREX and leaves Keycloak at its existing public URL.

The bundled-Keycloak template expects certificate files named after both public hosts:

- `${LAREX_PUBLIC_HOST}.crt` / `${LAREX_PUBLIC_HOST}.key`
- `${KEYCLOAK_PUBLIC_HOST}.crt` / `${KEYCLOAK_PUBLIC_HOST}.key`

The external-Keycloak template requires only the LAREX certificate pair.

## Security Notes

Do not commit populated `.env.prod` files. At minimum, protect:

- `POSTGRES_PASSWORD`
- `KEYCLOAK_POSTGRES_PASSWORD`
- `KEYCLOAK_ADMIN_PASSWORD`
- `KEYCLOAK_ADMIN_CLIENT_SECRET`
- `LAREX_INITIAL_ADMIN_TEMP_PASSWORD`
- `NUXT_SESSION_PASSWORD`
- `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET`
- `MAIL_PASSWORD`
- `LAREX_ACTION_ENDPOINT_SECRET_ENCRYPTION_KEY`
- `LAREX_ACTION_ENDPOINT_SECRET_*`

## IIIF Request Scheduling

IIIF previews and image downloads use separate worker pools. The deployment default for image download pacing is:

```bash
LAREX_IIIF_DOWNLOAD_MIN_INTERVAL_MS=100
LAREX_IIIF_MAX_IMAGE_DOWNLOAD_BYTES=536870912
```

This value is the minimum interval between download starts to the same remote host. Set it to `0` to disable fixed pacing. Adaptive cooldown still applies when a server returns HTTP 429 or HTTP 503 with `Retry-After`.

`LAREX_IIIF_MAX_IMAGE_DOWNLOAD_BYTES` is the hard limit for a single image response (512 MiB by
default). Downloads are also bounded by the workspace's live quota. LAREX stops the response stream
as soon as either limit is crossed and validates the downloaded JPEG, PNG, GIF, TIFF, or WebP
content before storing it.

A global administrator can override the deployment value at runtime from **Admin → IIIF Settings**. The override is stored in the database and takes precedence until it is reset. Resetting restores the current deployment default.

## Long-Running Exports

Project and dataset downloads use streamed HTTP responses. The backend allows 30 minutes for a
stream by default:

```bash
LAREX_ASYNC_REQUEST_TIMEOUT=30m
```

Increase this duration when very large multi-project exports regularly take longer. A reverse proxy
in front of LAREX must allow at least the same response duration; otherwise it can still truncate the
download before the ZIP archive is finalized.

## Project Package Import Limits

Project package previews extract uploaded ZIP files into a temporary directory before validation.
The following limits prevent oversized archives and excessive compression from exhausting server
storage:

| Variable | Default | Purpose |
| --- | ---: | --- |
| `LAREX_PROJECT_PACKAGE_MAX_ARCHIVE_BYTES` | `134217728` | Maximum compressed package bytes read by the extractor |
| `LAREX_PROJECT_PACKAGE_MAX_ENTRIES` | `100000` | Maximum ZIP entries, including directories |
| `LAREX_PROJECT_PACKAGE_MAX_ENTRY_BYTES` | `536870912` | Maximum extracted bytes for one entry |
| `LAREX_PROJECT_PACKAGE_MAX_TOTAL_BYTES` | `2147483648` | Maximum extracted bytes across the package |
| `LAREX_PROJECT_PACKAGE_MAX_DESCRIPTOR_BYTES` | `16777216` | Maximum bytes parsed from one manifest, page, or resource JSON descriptor |
| `LAREX_PROJECT_PACKAGE_MAX_COMPRESSION_RATIO` | `200` | Maximum uncompressed-to-compressed ratio for one entry |
| `LAREX_PROJECT_PACKAGE_PREVIEW_MAX_CACHED_BYTES` | `4294967296` | Approximate cumulative extracted-byte budget for pending previews |
| `LAREX_PROJECT_PACKAGE_PREVIEW_MAX_SESSIONS` | `64` | Maximum pending previews within the cumulative cache budget |
| `LAREX_PROJECT_PACKAGE_PREVIEW_EXPIRE_MINUTES` | `30` | Lifetime of an unconfirmed preview |

Keep the compressed limit at least as large as Spring's multipart file limit when packages are
expected to use the full upload allowance. The preview cache uses byte-weighted eviction while
reserving a minimum weight per session, so it enforces both the cumulative byte budget and session
ceiling. Rejected or evicted previews are removed from temporary storage.

## Portable Admin Dumps

Admin **Backup** verify and reseed jobs use a separate, larger extraction budget
because one portable dump can contain many project packages:

| Variable | Default | Purpose |
| --- | ---: | --- |
| `LAREX_BACKUP_OUTPUT_DIR` | `/mnt/data/backups` | Container directory used for portable dumps and reseed completion markers |
| `LAREX_BACKUP_MOUNT_SOURCE` | `backup_data` | Compose mount source for the output directory; use a host path for direct host access |
| `LAREX_BACKUP_MAX_ARCHIVE_BYTES` | `21474836480` | Maximum compressed dump size (20 GiB) |
| `LAREX_BACKUP_MAX_ARCHIVE_ENTRIES` | `500000` | Maximum ZIP entries |
| `LAREX_BACKUP_MAX_ARCHIVE_ENTRY_BYTES` | `5368709120` | Maximum extracted size of one entry (5 GiB) |
| `LAREX_BACKUP_MAX_ARCHIVE_TOTAL_BYTES` | `107374182400` | Maximum cumulative extracted size (100 GiB) |
| `LAREX_BACKUP_MAX_ARCHIVE_COMPRESSION_RATIO` | `200` | Maximum ratio for one ZIP entry |

These settings do not limit host-side full-instance `.tar.gz` snapshots. Those are
created and restored by the operator script rather than uploaded through the
backend. The output directory is deployment configuration and cannot be changed
from the Admin Dashboard.

Advanced worker-pool overrides are:

| Variable | Default | Purpose |
| --- | ---: | --- |
| `LAREX_IIIF_MAX_IMAGE_DOWNLOAD_BYTES` | `536870912` | Maximum bytes accepted for one IIIF image |
| `LAREX_IIIF_PREVIEW_ASYNC_CORE_POOL` | `2` | Core IIIF preview workers |
| `LAREX_IIIF_PREVIEW_ASYNC_MAX_POOL` | `4` | Maximum IIIF preview workers |
| `LAREX_IIIF_PREVIEW_ASYNC_QUEUE` | `100` | Pending preview capacity |
| `LAREX_IIIF_DOWNLOAD_ASYNC_CORE_POOL` | `1` | Core IIIF download workers |
| `LAREX_IIIF_DOWNLOAD_ASYNC_MAX_POOL` | `2` | Maximum IIIF download workers |
| `LAREX_IIIF_DOWNLOAD_ASYNC_QUEUE` | `50` | Pending download capacity |
| `LAREX_IIIF_WORKER_LEASE_DURATION_MS` | `120000` | Time before an unresponsive import worker's job is reclaimed |
| `LAREX_IIIF_WORKER_HEARTBEAT_INTERVAL_MS` | `30000` | Interval for renewing active import leases |
| `LAREX_IIIF_WORKER_RECOVERY_INTERVAL_MS` | `5000` | Interval for detecting expired leases and pending jobs |

IIIF import progress is committed canvas by canvas. If a backend process stops, another worker reclaims
the job after its lease expires and resumes at the first canvas without a committed result.

## LAREX Action Endpoint Secrets

Action processor YAML uses `endpoint.auth.secretRef` instead of storing raw secrets.

For example:

```yaml
endpoint:
  url: https://ocr.example.org/dispatch
  auth:
    type: hmac
    secretRef: ocr-processor-v1
```

LAREX resolves that `secretRef` from an admin-managed endpoint secret first. Create it in **Admin → Actions → Endpoint Secrets**. The server generates a strong value, reveals it once, and stores only an encrypted value in the database. Set the revealed value in the processor service:

```bash
LAREX_DISPATCH_HMAC_SECRET="generated-secret-from-larex"
```

The backend needs `LAREX_ACTION_ENDPOINT_SECRET_ENCRYPTION_KEY` to create, rotate, and decrypt database-backed endpoint secrets. Keep this key stable across restarts and backups.

Env-based backend secrets remain supported as fallback. If no admin-managed secret exists for a ref, LAREX checks:

```bash
LAREX_ACTION_ENDPOINT_SECRET_OCR_PROCESSOR_V1="long-random-shared-secret"
```

For bundled processors that start together with LAREX, use this fallback pattern so both containers receive the same value at startup. The admin secret list shows discoverable fallback refs as `Env fallback`, but LAREX cannot rotate or delete those values because the deployment environment is the source of truth.

For fallback secrets, the same value must also be present in the processor deployment, usually as `LAREX_DISPATCH_HMAC_SECRET`. Rotate admin-managed secrets from the UI; rotate fallback secrets by updating both environments and restarting or redeploying both services.

Official processor services use a separate `.env.actions` created from
`deployment/env/.env.actions.example`. This keeps processor image versions,
resource settings, callback policy, and HMAC secrets independent of the core LAREX
environment. See [Official Action Services](/deployment/official-action-services).
