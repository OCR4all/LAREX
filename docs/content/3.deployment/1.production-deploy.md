# Production Deployment

LAREX supports three deployment paths:

| Setup | When to use it | Command shape |
|------|-----------------|---------------|
| Local dev | Day-to-day development with source mounts | `docker compose up -d` |
| Local production-like | Rehearse production images and auth flows on `*.localhost` | `compose.prod.base.yaml` + `compose.prod.auth.bundled-keycloak.yaml` + `compose.prod.local.yaml` |
| Opinionated production | Real deployment behind your own reverse proxy | `compose.prod.base.yaml` + auth overlay + publish/Nginx overlay |

The default production stance is: run LAREX behind your own reverse proxy. The bundled production compose files bind frontend and bundled Keycloak to loopback by default and keep the backend internal-only.

## SELinux Hosts

On SELinux-enabled hosts (for example Fedora, RHEL, and CentOS), bind mounts need SELinux relabel options.

LAREX compose files use `:Z`/`,Z` for bind mounts because those mounts are single-container in the default setup.

If you customize deployment to share one host path across multiple containers, switch that specific bind mount to `:z` instead.

## Decision Tree

- Use local dev for source-mounted development.
- Use local production-like to test production images on `larex.localhost` and `keycloak.localhost`.
- Use opinionated production for real users.

For production:

- bundled Keycloak is the default
- external Keycloak is a small auth override
- bundled Nginx is an optional web-server override
- self-hosted docs are an optional docs override

## Commands

### Local production-like

```bash
cp deployment/env/.env.prod.local.example .env.prod.local

docker compose --env-file .env.prod.local \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.local.yaml \
  up -d
```

This exposes:

- `http://larex.localhost`
- `http://keycloak.localhost`
- `http://mail.localhost`

To include self-hosted docs, add `-f compose.prod.local.docs.yaml`:

```bash
docker compose --env-file .env.prod.local \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.local.yaml \
  -f compose.prod.local.docs.yaml \
  up -d
```

This also exposes:

- `http://docs.localhost`

### Production default

```bash
cp deployment/env/.env.prod.example .env.prod

docker compose --env-file .env.prod \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.publish.localhost.yaml \
  up -d
```

This publishes:

- frontend on `127.0.0.1:3000`
- bundled Keycloak on `127.0.0.1:8090`

The backend stays internal to the compose network.

To include self-hosted docs, add `-f compose.prod.docs.yaml`:

```bash
docker compose --env-file .env.prod \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.publish.localhost.yaml \
  -f compose.prod.docs.yaml \
  up -d
```

This additionally publishes docs on `127.0.0.1:3001`.

### Production with external Keycloak

```bash
docker compose --env-file .env.prod \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.external-keycloak.yaml \
  -f compose.prod.publish.localhost.yaml \
  up -d
```

### Production with bundled Nginx

```bash
docker compose --env-file .env.prod \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.publish.localhost.yaml \
  -f compose.prod.nginx.yaml \
  up -d
```

`compose.prod.nginx.yaml` is optional. It expects operator-provided certificates and does not manage ACME or LetsEncrypt for you.

## Environment Setup

Copy one of the committed example files:

```bash
cp deployment/env/.env.prod.example .env.prod
cp deployment/env/.env.prod.local.example .env.prod.local
```

Production operators usually need to edit only:

- `LAREX_PUBLIC_HOST`
- `KEYCLOAK_PUBLIC_HOST`
- `KEYCLOAK_REALM`
- `LAREX_BIND_IP`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `KEYCLOAK_ADMIN`
- `KEYCLOAK_ADMIN_PASSWORD`
- `KEYCLOAK_ADMIN_CLIENT_SECRET`
- `NUXT_SESSION_PASSWORD`
- `NUXT_OAUTH_KEYCLOAK_CLIENT_SECRET`
- `LAREX_INITIAL_ADMIN_*`
- `MAIL_*`

The compose files derive the usual redirect URLs, issuer URLs, and CORS origin from those values.

## Keycloak Bootstrap

Bundled Keycloak imports `config/keycloak/larex.bootstrap.realm.json` automatically. The template creates:

- the frontend OAuth client
- the backend service-account client
- the `GLOBAL_ADMIN` realm role
- one initial admin user from `LAREX_INITIAL_ADMIN_*`

If you use external Keycloak, import that template manually or recreate the equivalent client, role, redirect, and web-origin settings in your existing realm.

## Verification

After startup:

```bash
docker compose --env-file .env.prod \
  -f compose.prod.base.yaml \
  -f compose.prod.auth.bundled-keycloak.yaml \
  -f compose.prod.publish.localhost.yaml \
  ps
```

Check:

- your reverse proxy can reach frontend on `127.0.0.1:3000`
- bundled Keycloak, if used, is reachable on `127.0.0.1:8090`
- the backend is not exposed publicly

After the first successful login, rotate bootstrap passwords and temporary admin credentials.
