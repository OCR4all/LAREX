# Image Delivery

LAREX uses resized presentation images for browsing and editing. This reduces transfer size and display memory while keeping original files available for full-resolution viewing, downloads, exports, and Actions. Display memory depends on an image's pixel dimensions, even when its compressed file is small.

## Display modes

| Tier | Maximum longest edge | Used for |
| --- | ---: | --- |
| Thumbnail | 320 pixels | Sidebar previews |
| Overview | 1,600 pixels | Image carousel |
| Detail | 3,200 pixels | Editor canvas, detail viewer, and image comparison |
| Original | Native dimensions | Explicit Full Resolution viewing |

Preview tiers preserve aspect ratio, do not upscale smaller images, and return JPEG display derivatives. They do not replace the original image in processing or training inputs.

The editor's resolution control switches the active canvas between **Preview** and **Full Resolution**. Its tooltip identifies the selected mode, and a loading indicator appears while the image loads. Selecting another image returns that canvas to Preview mode. See [Editor Interface](/user-guide/editor-interface) and [Projects](/user-guide/projects) for the viewing controls.

Full Resolution streams JPEG, PNG, WebP, GIF, and BMP images without decoding the complete raster on the server. Other supported formats are converted to a browser-compatible PNG. Full-resolution viewing has no application pixel-size cap; rendering depends on the browser and graphics device's capabilities.

Failed previews show an error and a retry control. They do not automatically load the original file. Image comparison provides independent loading and retry states for each side.

## Annotation coordinates and orientation

Annotations use the original image's pixel coordinates at every display resolution. The editor maps previews and text-line cutouts onto those coordinates, so changing resolution does not change annotation geometry.

Display images use the source's stored pixel orientation. EXIF rotation and mirroring are ignored for preview generation and omitted from streamed JPEG, PNG, and WebP display responses. The stored original, including its metadata, remains unchanged for downloads, exports, and Actions.

## Presentation API

Project images and dataset-copy images have presentation endpoints:

```text
GET /api/v1/projects/{projectId}/pages/images/{imageId}/presentation?size=detail
GET /api/v1/workspaces/{workspaceId}/datasets/{datasetId}/items/{itemId}/images/{imageId}/presentation?size=detail
```

The `size` parameter accepts `thumbnail`, `overview`, `detail`, or `original`. Project requests default to `overview`; dataset-copy requests default to `detail`. Requests through the frontend proxy use `/api/` in place of `/api/v1/`.

Responses include `X-Original-Width` and `X-Original-Height` headers containing the stored source dimensions. Clients that display annotations must use these dimensions rather than the preview raster's dimensions.

Each request requires access to its project image or dataset item. Authorization is checked before accessing cached derivatives. Successful responses use private HTTP caching. Conversion failures are not cached; busy or timed-out conversions return a retryable response with `Retry-After`.

The legacy project-image thumbnail endpoint redirects to the thumbnail presentation endpoint and does not fall back to original bytes.

## Preview generation configuration

Configure preview generation under `larex.image-presentation` in `application.yaml`, or use the corresponding environment variables:

| Environment variable | Default | Purpose |
| --- | --- | --- |
| `LAREX_PRESENTATION_QUEUE_CAPACITY` | `8` | Maximum queued conversions per backend instance |
| `LAREX_PRESENTATION_REQUEST_TIMEOUT` | `45s` | Maximum wait for a conversion result |
| `LAREX_PRESENTATION_DECODE_TIMEOUT` | `30s` | Conversion worker execution deadline |
| `LAREX_PRESENTATION_WORKER_HEAP_MIB` | `384` | Java heap available to each conversion worker, in MiB |
| `LAREX_PRESENTATION_MAX_SOURCE_PIXELS` | `500000000` | Maximum source pixel count for preview generation |
| `LAREX_PRESENTATION_MAX_SOURCE_DIMENSION` | `100000` | Maximum source width or height for preview generation |
| `LAREX_PRESENTATION_MAX_SOURCE_BYTES` | `536870912` | Maximum source file size for preview generation, in bytes |
| `LAREX_PRESENTATION_MAX_DISK_CACHE_BYTES` | `268435456` | Maximum persistent derivative cache size, in bytes |
| `LAREX_PRESENTATION_DISK_RETENTION` | `7d` | Idle retention period for cached derivatives |
| `LAREX_PRESENTATION_CACHE_DIRECTORY` | `${file.upload-dir}/.presentations` | Persistent derivative cache directory |

Each backend instance runs one conversion at a time. Conversion workers run in separate processes and are terminated when interrupted or when their execution deadline expires. The heap setting limits Java heap allocation, not total process memory.

Preview source-size limits do not apply to explicit original-image streams. Formats requiring conversion still use the conversion worker's resource limits. Deployments with multiple backend instances should account for their combined conversion workload.

## Caching and storage

Generated previews are cached in memory and on disk. The disk cache survives backend restarts and can be regenerated from the original files. It does not replace backups of those originals.

Cache entries are associated with the source path, file size, modification time, requested tier, and generation policy. When replacing a source file in place, update its modification time so cached derivatives are invalidated. Cache maintenance removes expired entries and derivatives whose source files were changed or deleted. Incomplete or corrupt entries are regenerated when requested.

The browser shares preview loads between consumers, prioritizes visible images over prefetching, and cancels abandoned requests. Decoded previews and automatic preview textures have bounded caches. Explicit full-resolution images are excluded from the automatic preview memory budget.

## Performance considerations

The first preview request may take longer because the source must be read and decompressed. Subsequent requests can reuse a cached derivative. Reducing the output dimensions does not necessarily remove the source-decoding cost.

Previews support page navigation, layout editing, comparison, and moderate zoom. Use Full Resolution for fine print or pixel-level inspection. Tile-based deep zoom is not currently available, so full-resolution viewing loads the complete image in the browser.
