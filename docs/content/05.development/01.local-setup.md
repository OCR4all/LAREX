# Native Service Development

This page is intentionally not the default installation path. LAREX is designed to run locally through Docker, and the actively supported contributor workflow is [Docker Development](/development/docker-setup).

Use native service development only when you need direct IDE debugging, framework-specific commands, or faster iteration on a single service. You still use Docker for shared infrastructure.

## When To Use This

| Goal | Recommended setup |
| --- | --- |
| Try or review LAREX locally | [Docker Development](/development/docker-setup) with `task docker:up` |
| Contribute code with development containers | [Docker Development](/development/docker-setup) |
| Debug Spring Boot in an IDE | This page |
| Run Nuxt tooling directly | This page |
| Rehearse production images | [Production Deployment](/deployment/production-deploy#local-production-like) |

## Required Native Tools

Install these only for the services you run outside Docker:

| Tool | Needed for |
| --- | --- |
| Java 25 | Backend `./gradlew bootRun`, tests, and local Gradle tasks |
| Node.js 22.18+ | Frontend, docs, and Keycloak theme tooling |
| pnpm | Frontend, docs, and Keycloak theme dependency management |
| Taskfile, optional | Root and package command shortcuts |

You do not need a local PostgreSQL, Keycloak, Traefik, or Mailpit installation. Run those with Docker.

## Start Shared Infrastructure

Start only the infrastructure containers:

```bash
task docker:infra
```

This starts application PostgreSQL, Keycloak, and Traefik, together with the Keycloak PostgreSQL and socket-proxy dependencies from `compose.yaml`. Start `mailpit` separately when testing email flows: `docker compose up -d mailpit`.

Check status:

```bash
task status
```

## Install JavaScript Dependencies

Only do this when running frontend, docs, or the Keycloak theme directly:

```bash
task install
```

This installs dependencies for:

- `docs`
- `frontend`
- `keycloak-theme`

Backend dependencies are resolved by the Gradle wrapper when backend tasks run.

## Configure Host Networking

The committed defaults use Docker service names (`postgres`, `keycloak`, `app`,
`frontend`, `mailpit`), which a host process cannot normally resolve. Configure
the service you run natively before starting it.

For a native backend, export these in its terminal:

```bash
export SPRING_DATASOURCE_URL=jdbc:postgresql://localhost:5432/larex_backend
export SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWK_SET_URI=http://keycloak.localhost/realms/larex-dev/protocol/openid-connect/certs
export KEYCLOAK_ADMIN_SERVER_URL=http://keycloak.localhost
export MAIL_ENABLED=false
export LAREX_UPLOAD_DIR="$PWD/backend/uploads"
export LAREX_NOTIFICATIONS_BRIDGE_URL=http://localhost:3000/api/notifications/broadcast
```

For a native frontend, create `frontend/.env` from `frontend/.env.example`, set
`NUXT_API_BASE_INTERNAL=http://localhost:8080/api/v1`, and provide a random
`NUXT_SESSION_PASSWORD` of at least 32 characters. Keep the OAuth redirect URL
`http://larex.localhost/auth/keycloak` and make sure `keycloak.localhost` reaches
Traefik on your host.

Traefik discovers Docker containers; starting infrastructure alone does not give
a native Nuxt server a `larex.localhost` route. To use the shipped realm unchanged,
configure a local reverse proxy on that hostname to your native frontend, with
WebSocket forwarding, replacing Traefik's port-80 listener as needed. An alternative
is to configure the realm's allowed redirect/web-origin and the Nuxt redirect URL
for `http://localhost:3000`; apply these changes in the existing realm's admin console.

If only one service runs natively, adapt both directions of communication: a
container cannot reach the host through `localhost`. Provide a host address
reachable by that container for the backend API or notification bridge.

Native Action testing also needs reachable processor and callback URLs; the
Docker-only defaults are not valid on the host. The full container workflow is
the simplest way to exercise the entire Action lifecycle.

## Backend Directly On The Host

Run from the repository root:

```bash
task backend:dev
```

Equivalent:

```bash
cd backend
./gradlew bootRun
```

The backend listens on `http://localhost:8080`. Traefik also routes `http://api.localhost` to the Docker backend when the backend container is running, so avoid running the Docker `app` service and a native backend on the same port at the same time.

### Debug Mode

```bash
cd backend
./gradlew bootRun --debug-jvm
```

Attach your IDE debugger to port `5005`; execution waits until a debugger connects.
The current `task backend:dev:debug` shortcut passes `-Pdebug`, but the build does
not consume that property. Use the direct command above for native debugging.

## Frontend Directly On The Host

```bash
task frontend:dev
```

Equivalent:

```bash
cd frontend
pnpm dev
```

The Nuxt dev server listens on `http://localhost:3000`. Complete the [host networking configuration](#configure-host-networking) before testing sign-in or backend calls.

## Docs Directly On The Host

```bash
task docs:dev
```

Equivalent:

```bash
cd docs
pnpm dev
```

The docs app is independent from the authenticated frontend. Running it directly is useful while editing documentation, but it is not required to run LAREX.

## Typical Native Workflow

```bash
# Terminal 1: shared infrastructure
task docker:infra

# Terminal 2: export the backend host settings above, then start
task backend:dev

# Terminal 3: configure frontend/.env and routing above, then start
task frontend:dev
```

If you only work on one service, run the rest in Docker instead.

## Useful Checks

```bash
task backend:test
task frontend:lint
task frontend:typecheck
task docs:build
```

Run all checks:

```bash
task test
```

## Common Native Issues

| Symptom | Check |
| --- | --- |
| Backend port is already in use | Stop the Docker `app` container or the other process using `8080`. |
| Frontend port is already in use | Stop the Docker `frontend` container or choose another Nuxt port. |
| Login loops or callback errors | Use the configured local hostnames, especially `http://larex.localhost` and `http://keycloak.localhost`. |
| Backend cannot connect to the database | Confirm `task docker:infra` is running and `postgres` is healthy. |
| JavaScript install fails | Use the repo’s lockfiles and run installs from the relevant package directory or through `task install`. |
