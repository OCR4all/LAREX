---
title: Dynamic Parameter Values
description: Let the processor supply the allowed values of an Action parameter at run time.

  icon: i-lucide-list-checks
---

Actions can constrain a parameter to values discovered by the processor, for
example the models installed on its host. Register zero-argument synchronous or
asynchronous providers with the FastAPI adapter:

```python
from larex_actions import ParameterChoice


def discover_models():
    return [
        ParameterChoice(value="model-a", label="Model A"),
        ParameterChoice(value="model-b", label="Model B"),
    ]


app = create_larex_action_app(
    processor_id="my-processor",
    dispatch_secret=secret,
    handler=process,
    parameter_value_providers={"models": discover_models},
)
```

The adapter serves the signed `/parameter-values` route, including configured
route prefixes, advertises `capabilities.parameterValueDiscovery` during
preflight, and limits each provider to 1,000 unique primitive choices. Configure
the matching URL and provider name in the Action YAML; see
[Allowed values](/actions/yaml-reference#allowed-values).

LAREX calls the providers again immediately before a run, so the returned values
are an authoritative allowlist rather than UI suggestions.

## Default choices

Mark the choice LAREX should preselect with `default=True`:

```python
ParameterChoice(value="model-a", label="Model A", default=True)
```

- A YAML `default` that the provider still offers takes precedence. The marked
  choice is used when the YAML sets no `default`, or sets one that is no longer
  offered. See [Defaults](/actions/yaml-reference#defaults) for the full order.
- Mark one choice for a single-value parameter; LAREX rejects a response with
  several. Parameters with `multiple: true` may have several marked choices.
- The SDK sends the flag only when LAREX announces
  `capabilities.parameterChoiceDefaults` in the discovery request, so providers
  can set it without breaking older installations.
