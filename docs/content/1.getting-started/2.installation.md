# Installation

The supported administrator installation artifact is a versioned deployment bundle built from this page. It uses the pre-built LAREX images and contains the selected Docker Compose files, required Keycloak or Nginx assets, environment templates, backup utilities, and an installation runbook. You do not need to clone the repository or install Node.js, pnpm, Java, or Gradle.

Use [Docker Development](/development/docker-setup) instead when you are contributing code and need development images with source mounts.

::warning
**Pre-1.0 database compatibility:** Before the 1.0 release, the current Flyway
migrations will be consolidated into a new initial schema. Databases created by
pre-1.0 builds will not have a supported in-place upgrade path to 1.0 and must be
recreated. Treat current development instances as disposable and do not keep
important data only in them. Starting with 1.0, released migrations will remain
immutable and upgrades will use normal forward migrations.
::

## Prerequisites

Install these tools on the server:

| Tool | Why |
| --- | --- |
| Docker Engine with Docker Compose v2 | Runs and manages every selected service |
| Python 3 | Generates secrets locally through the included bootstrap script |
| `jq`, `tar`, and `sha256sum` or `shasum` | Creates and verifies full-instance backups |
| `unzip` | Extracts the downloaded bundle |

Extract the ZIP, open its generated `README.md`, and follow the exact validation and startup commands. The bundle deliberately contains no credentials. Its bootstrap script creates `.env.prod` and, when Kraken is selected, `.env.actions` from the configured templates.

For the complete bundle attached to a GitHub release, download its accompanying
`.zip.sha256` file and `larex-release-<version>.json` manifest. Verify the external
ZIP checksum before extraction and the bundled `SHA256SUMS` afterward. The release
manifest binds that bundle to the source commit and immutable container-image
digests. Released images are vulnerability-gated, signed with Sigstore, and carry
SPDX SBOM and maximum-mode provenance attestations.

## Supported Artifact Lifecycle

Each bundle records its image tag in `VERSION` and pins that tag in the environment template. For production, select a released version rather than a mutable branch or snapshot tag. Upgrade by changing `LAREX_IMAGE_TAG`, validating the resolved Compose model, taking a backup, and applying the generated pull and startup commands.

The complete, uncustomized deployment bundle, checksum, and immutable release
manifest are also attached to every GitHub release. The wizard is the preferred
path because it removes unused fragments and generates instructions for the
selected topology.

## Common Issues

| Symptom | Check |
| --- | --- |
| Browser cannot reach LAREX | Confirm DNS and the selected reverse proxy route point to the generated upstream. |
| Login redirects fail | Confirm the LAREX hostname, Keycloak hostname, realm, clients, and redirect URIs match the generated environment. |
| Bundled Nginx does not start | Confirm the certificate/key pairs required by the selected authentication mode exist in `deployment/nginx/certs`. |
| Kraken remains unhealthy | Review its CPU, memory, device, model, and temporary-storage settings in `.env.actions`. |
| SELinux blocks mounted files | Keep the shipped `:Z` labels on bind mounts for Fedora/RHEL-style hosts. |
