# Installation

The supported way to run LAREX locally is Docker Compose. You do not need Node.js, pnpm, Java, Gradle, or a local PostgreSQL installation for this path. Those tools are only useful when you intentionally work on individual services outside Docker.

Use this page when you want to try LAREX, review the application, or run the full stack on your machine. Use [Docker Development](/development/docker-setup) when you are contributing code and want the development images with source mounts.

::warning
**Pre-1.0 database compatibility:** Before the 1.0 release, the current Flyway
migrations will be consolidated into a new initial schema. Databases created by
pre-1.0 builds will not have a supported in-place upgrade path to 1.0 and must be
recreated. Treat current development instances as disposable and do not keep
important data only in them. Starting with 1.0, released migrations will remain
immutable and upgrades will use normal forward migrations.
::

## What Docker Starts

The default local stack is defined in `compose.yaml` and starts:

| Service | Purpose | Local route |
| --- | --- | --- |
| `frontend` | Nuxt application and browser-facing BFF routes | `http://larex.localhost` |
| `app` | Spring Boot backend API | `http://api.localhost` |
| `postgres` | Application database | internal plus `localhost:5432` |
| `keycloak` | Local identity provider | `http://keycloak.localhost` |
| `keycloak-postgres` | Keycloak database | internal |
| `traefik` | Local reverse proxy for `*.localhost` routes | `localhost:80` |
| `mailpit` | Local mail catcher | `http://mail.localhost` |
| `mock-action-processor` | Example LAREX Actions processor | `http://mock-action-processor.localhost` |

The docs app is independent and optional. Add it only when you want to self-host the docs locally.

## Prerequisites

Install only:

| Tool | Why |
| --- | --- |
| Docker Desktop or Docker Engine with Docker Compose | Runs every LAREX service in containers |
| Git | Clones the repository |
| Taskfile, optional | Runs the documented shortcuts such as `task docker:up` |

If you do not install Taskfile, use the equivalent `docker compose ...` commands shown below.

## Clone The Repository

```bash
git clone <repository-url>
cd larex
```

## Start LAREX

With Taskfile:

```bash
task docker:up
```

Without Taskfile:

```bash
docker compose -f compose.yaml up -d
```

Open:

- `http://larex.localhost` for LAREX
- `http://keycloak.localhost` for Keycloak
- `http://mail.localhost` for local email

Most systems resolve `*.localhost` automatically. If your browser or OS does not, add these hostnames to `/etc/hosts`:

```text
127.0.0.1 larex.localhost
127.0.0.1 api.localhost
127.0.0.1 keycloak.localhost
127.0.0.1 mail.localhost
127.0.0.1 mock-action-processor.localhost
127.0.0.1 docs.localhost
```

## Start With Docs

```bash
task docker:up:docs
```

Equivalent Docker Compose command:

```bash
docker compose -f compose.yaml -f compose.dev.docs.yaml up -d
```

Then open `http://docs.localhost`.

## Rebuild Images

Use this after Dockerfile changes, dependency changes, or when you want a clean rebuild of local images:

```bash
task docker:up:build
```

Equivalent:

```bash
docker compose -f compose.yaml up -d --build
```

## Check Status And Logs

```bash
task docker:ps
task docker:logs
```

Useful focused logs:

```bash
task docker:logs:backend
task docker:logs:frontend
task docker:logs:docs
```

Without Taskfile:

```bash
docker compose -f compose.yaml ps
docker compose -f compose.yaml logs -f
```

## Stop LAREX

Stop containers but keep database volumes:

```bash
task docker:down
```

Remove containers and volumes. This deletes local database state:

```bash
task docker:down:clean
```

## Optional Native Toolchains

Native dependencies are not part of installation. Install them only if you are developing a service outside Docker:

| Tool | Only needed for |
| --- | --- |
| Java 25 | Running `backend` directly with `./gradlew bootRun` |
| Node.js and pnpm | Running `frontend`, `docs`, or `keycloak-theme` directly |
| Gradle | Not required; the backend uses `backend/gradlew` |

The actively supported contributor path is the Docker development setup. Native service execution is useful for maintainers who want IDE debugging or direct framework tooling, but it is not required to run LAREX.

## Local Credentials

Default local credentials are for development only.

| Service | URL | Default credentials |
| --- | --- | --- |
| Keycloak Admin | `http://keycloak.localhost/admin` | `admin` / `admin` |

Application user provisioning depends on the current Keycloak realm configuration. See [Keycloak Setup](/deployment/keycloak-setup) when you need to change realms, roles, or client settings.

## Common Issues

| Symptom | Check |
| --- | --- |
| `larex.localhost` does not load | Run `task docker:ps` and confirm `traefik`, `frontend`, and `app` are running. |
| Port 80 is already in use | Stop the conflicting local web server or change the Traefik port in `compose.yaml`. |
| Login redirects fail | Confirm you are using `http://larex.localhost`, not `http://localhost:3000`, for the Docker stack. |
| Containers start with stale state | Use `task docker:down:clean` only when you are willing to delete local data. |
| SELinux blocks mounted files | The compose files already use `:Z` labels for private bind mounts; keep those labels on Fedora/RHEL-style hosts. |
