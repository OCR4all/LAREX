Use **Assignments** to coordinate human review. An Assignment holds a title, description, status, priority, members, due date, and Tasks. A Task can be a general checklist item or linked to a specific page.

The source/API calls an Assignment a `Task` and its checklist items `Subtask`s. In the interface and this guide, **Assignment** means the container and **Task** means an item inside it. Processor executions are [Actions](/user-guide/larex-actions); their progress appears in **Jobs**.

## Create an Assignment

Workspace owners and curators can manage Assignments. Open **Assignments** in the selected workspace and choose **Create Assignment**.

1. Give it a title that states the outcome, such as `Proofread chapter 1`.
2. Add instructions, a priority, and an optional due date.
3. Select the workspace members responsible for the work.
4. In the page-selection step, optionally choose pages. Pick one or more projects; their pages appear together in one table that you can search, sort, and filter by tag, annotation, and page state. Each selected page becomes a Task, balanced across the selected members.
5. Create the Assignment and review its Tasks tab.

You can add more page Tasks later from the Assignment details. General Tasks are useful for checklist work that does not map to one page.

**Check:** the expected people and pages appear. Linking a page gives the Assignment context; completion is tracked through its page Tasks.

## Find and organize work

The Assignments overview offers **Table** and **Board** views. Filter by status or **Assigned to me**, and search by title. Priorities are **Low**, **Medium**, **High**, and **Urgent**.

An Assignment's status follows its Tasks; you don't set it by hand:

| Status | When |
|---|---|
| **Open** | No Task is complete yet, or the Assignment has no Tasks |
| **In progress** | At least one Task is complete |
| **Completed** | All Tasks are complete |
| **Paused** | A curator paused the Assignment |

Reopening a Task moves a Completed Assignment back to **In progress**. Each automatic change appears in the Activity tab. The Board shows one column per status and is read-only.

**Pause** an Assignment from its details to put the work on hold: its Tasks leave the editor and review queues, it stops changing page states, and reminders stop. **Resume** picks the status up from its Tasks again.

**Archive** an Assignment when it no longer needs attention, for example once it is Completed; its details suggest this. Archived Assignments are hidden from the overview until you turn on **Show archived**, and they stop like paused ones. They can't be changed until you **Unarchive** them, but they can still be deleted.

Curators can use bulk controls to archive or unarchive selected Assignments, or change their priority or members.

Open an Assignment to see its **Tasks**, **Comments**, and **Activity** tabs. Comments record discussion; Activity helps explain changes to the Assignment. Due dates and reminders help schedule work, with delivery controlled by [notification preferences](/user-guide/account-and-notifications#choose-notifications).

## Complete page work

1. Open the page Task and enter the editor.
2. Correct its layout or transcription according to the instructions.
3. Save the annotation, or use the editor's save-and-complete action to finish the relevant Task with a save. If the project requires review, this action reads **Save + Submit for review**.
4. Confirm the Task is complete in the Assignment.
5. When the last Task is complete, the Assignment becomes **Completed** on its own.

Page Tasks allow reviewers to record progress without permission to restructure the Assignment. Creating, deleting, assigning others, or changing container details requires curator management capabilities.

## Page states and review

Every page is **Open**, **In review**, or **Done**.

| Action | Moves the page | Who can do it |
| --- | --- | --- |
| Submit for review | Open → In review | Any workspace member |
| Approve | In review → Done | Curators |
| Request changes | In review → Open | Curators, with an optional comment |
| Withdraw from review | In review → Open | The person who submitted the page |
| Mark as done | Open → Done | Any member, or curators only if the page requires review |
| Reopen | Done → Open | Any member, or curators only if the page requires review |

Pages in review are read-only for editors. Curators can still edit them and run Actions on them, so they can fix small errors without sending a page back. Done pages are read-only for everyone until reopened.

You can't withdraw a page or review it while someone else is editing it. Transient page locks and locked projects also block state changes; resolve the lock instead of repeating the action.

When a curator requests changes, the page's completed Tasks reopen in every Assignment that isn't paused or archived. Withdrawing or reopening a page reopens the Tasks of participating Assignments. A Completed Assignment returns to **In progress**, so the page appears in the editor's queue again. The editor gets a notification, and the comment appears in the Task panel when they open the page. Finishing those Tasks sends the page back to review, even if review isn't otherwise required. Pages without an Assignment can be found with the **Changes requested** filter in the project and the editor.

To see who changed a page's state and when, choose **Review history** from the page actions in the editor.

### Require review

There are two ways to make review mandatory:

- **For a project:** turn on **Require review for this project** in the project settings. **Require review in new projects** in the workspace settings sets the default for new projects, and saving it lets you apply the change to existing projects.
- **For an Assignment:** set **When page work finishes** to **Send the page to review**.

When review is required, editors can only submit a page, and only curators can mark it as done or reopen it.

### Update page state from Assignments

**When page work finishes** decides what an Assignment does to a page once all of the page's Tasks are complete:

| Setting | Effect |
| --- | --- |
| Keep the page state | The Assignment doesn't change page state. |
| Mark the page as done | The page becomes Done, or In review if its project requires review. |
| Send the page to review | The page becomes In review. |

An Assignment takes part if it uses one of the last two settings and isn't paused or archived. Tasks from all participating Assignments on a page count together:

| Situation | Resulting page state |
| --- | --- |
| No participating Assignments | Unchanged |
| A participating Task is still open | Open |
| All Tasks complete, page is Open | In review if review is required, otherwise Done |
| All Tasks complete, page is In review or Done | Unchanged |

A page can therefore stay Open after one person finishes their Task if another participating Assignment still has work for it. An Assignment's own status has no effect on page state.

## Review pages

Curators review pages from the **Assignments** page.

1. Open the **Review** tab, which shows the number of pages waiting. Filter by project, Assignment, or editor if you want to work through part of the queue.
2. Select **Open Review Queue** to go through the pages one at a time. Approving a page or requesting changes moves you to the next one.
3. Or select pages in the list to approve them or request changes in bulk.

The queue is shared by all curators. A page someone else is reviewing is marked and skipped, and the name of that curator is shown. Curators can approve pages they submitted themselves; the review history shows who did what.

## When progress looks wrong

Check the Assignment's linked page Tasks, whether synchronization is enabled, whether another synchronized Assignment covers the same page, and whether it is paused or archived. A processor job's success is separate from human review completion.
