# Assignments and page Tasks

Use **Assignments** to coordinate human review. An Assignment holds a title, description, status, priority, members, due date, and Tasks. A Task can be a general checklist item or linked to a specific page.

The source/API calls an Assignment a `Task` and its checklist items `Subtask`s. In the interface and this guide, **Assignment** means the container and **Task** means an item inside it. Processor executions are [Actions](/user-guide/larex-actions); their progress appears in **Jobs**.

## Create an Assignment

Workspace owners and curators can manage Assignments. Open **Assignments** in the selected workspace and choose **Create Assignment**.

1. Give it a title that states the outcome, such as `Proofread chapter 1`.
2. Add instructions, a status, priority, and optional due date.
3. Select the workspace members responsible for the work.
4. In the page-selection step, optionally choose pages. Each selected page becomes a Task, balanced across the selected members.
5. Create the Assignment and review its Tasks tab.

You can add more page Tasks later from the Assignment details. General Tasks are useful for checklist work that does not map to one page.

**Check:** the expected people and pages appear. Linking a page gives the Assignment context; completion is tracked through its page Tasks.

## Find and organize work

The Assignments overview offers **Table** and **Board** views. Filter by status or **Assigned to me**, and search by title. The status choices are **Open**, **In progress**, **Completed**, and **Cancelled**. Priorities are **Low**, **Medium**, **High**, and **Urgent**.

Curators can use supported bulk controls to update selected Assignments' status, priority, or members. Board moves follow the same permission checks as table actions.

Open an Assignment to see its **Tasks**, **Comments**, and **Activity** tabs. Comments record discussion; Activity helps explain changes to the Assignment. Due dates and reminders help schedule work, with delivery controlled by [notification preferences](/user-guide/account-and-notifications#choose-notifications).

## Complete page work

1. Open the page Task and enter the editor.
2. Correct its layout or transcription according to the instructions.
3. Save the annotation, or use the editor's save-and-complete action to finish the relevant Task with a save.
4. Confirm the Task is complete in the Assignment.
5. Review the Assignment's status and remaining Tasks before treating the whole Assignment as finished.

Page Tasks allow reviewers to record progress without permission to restructure the Assignment. Creating, deleting, assigning others, or changing container details requires curator management capabilities.

## Synchronize page workflow state

An Assignment can enable **Synchronize page workflow states**. This derives page state from its participating page Tasks, including Tasks in other synchronized Assignments.

| Situation | Derived page state |
| --- | --- |
| No participating Tasks, or only cancelled Assignments | Open |
| Every participating page Task is complete | Done |
| Some page Tasks remain open and at least one participating Assignment is In progress | In progress |
| Other unfinished work | Open |

Cancelled Assignments are excluded from synchronization. A page can therefore remain unfinished after one reviewer completes their Task if another synchronized Assignment still has work for that page.

You can also change page state directly from the state badge in the project/editor when permitted. The page states are **Open**, **In progress**, and **Done**. Done pages are protected against editing until reopened. A later synchronized Task update can recompute a state you changed manually.

Marking a page Done requires that another editor is not actively editing it. Transient page locks and locked projects can also block state changes; resolve the lock instead of repeatedly changing status.

## When progress looks wrong

Check the Assignment's linked page Tasks, whether synchronization is enabled, whether another synchronized Assignment covers the same page, and whether it is cancelled. A processor job's success is separate from human review completion.
