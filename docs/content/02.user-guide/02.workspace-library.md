# Workspace and Library

The library is the starting point for most LAREX work. It shows the projects available in the selected workspace and gives curators the tools to create projects, configure presets, invite members, and keep work organized.

## Workspaces

Each user has a personal workspace. Curators can also create team workspaces for collaborative projects.

| Workspace type | Use it for |
| --- | --- |
| Personal workspace | Private experiments, small imports, and material only one user should manage. |
| Team workspace | Shared annotation projects, curated collections, and work that needs role-based access. |

Use the workspace switcher to move between workspaces. The library, search, toolkit resources, queue, and settings all follow the currently selected workspace.

## Roles

Workspace roles control what users can do inside a team workspace.

| Role | Typical work |
| --- | --- |
| Owner | Workspace governance, metadata, ownership, and all curator tasks. |
| Curator | Project creation, resource management, member invitations, Action assignment, and review workflows. |
| Editor | Annotation, text correction, search, exports, and Actions that allow editor execution. |

Global roles are separate from workspace membership:

| Global role | Purpose |
| --- | --- |
| `GLOBAL_CURATOR` | Allows creating team workspaces; it does not grant membership of every workspace. |
| `GLOBAL_ADMIN` | Allows access to [Admin Dashboard](/user-guide/admin-dashboard/overview) pages and global system configuration. |

The backend is authoritative for permissions. Buttons may be hidden in the UI, but server-side authorization still decides whether an action is allowed.

## Create A Team Workspace

1. Open **Workspaces**.
2. Choose **New Workspace**.
3. Enter a name and optional description.
4. Invite members if you already know the team.
5. Assign each invite as **Curator** or **Editor**.
6. Create the workspace.

After creation, open **Workspace Settings** to manage members, presets, and storage information.

## Use The Library

The library table helps you find and open projects.

The table stays visible while project data refreshes after edits or processing jobs. Updated values appear when the refresh completes; the full loading indicator is reserved for loading a workspace's projects for the first time.

Common tasks:

- Search projects by name or metadata.
- Filter by tags, starred state, and table columns.
- Sort by project properties such as updated time or page count.
- Open a project page list.
- Open selected pages directly in the editor.
- Start project-level exports or Actions.
- Edit, share, or delete projects when your role allows it.

## Workspace Presets

Workspace presets make new projects consistent. Curators can define defaults for:

- tag set
- label set
- codec
- dictionary
- normalization profile
- validation ruleset
- text-index settings

Presets do not prevent a project from using a different resource later. They define the starting point for new projects. When saving changed defaults, the review dialog also offers:

| Scope | Existing projects |
| --- | --- |
| Future projects only | Keep their current settings. This is the default. |
| Fill missing project settings | Receive defaults only where settings are empty; explicit values are preserved. |
| Replace settings in all projects | Receive the changed defaults even where explicit choices exist. |

Propagation skips locked projects and reports affected/skipped counts. Review the preview before replacing settings across a workspace.

## Share Work

Project sharing is handled as a workspace transfer request. A curator can request to move or copy a project to another workspace and include an optional message. The receiving workspace then handles the transfer flow.

Use **copy** when both workspaces should keep their own version. Use **move** when ownership of the working project should transfer.

## When A Project Is Locked

Locked projects block mutation workflows even for curators and owners. Users can still inspect available information, but edits, uploads, deletes, and processor runs that would modify project data are blocked.

Locks may be applied by long-running jobs or administrative workflows. The UI shows the lock reason when LAREX has one.

## Permission boundaries

Workspace owners govern workspace metadata and ownership. Curators manage day-to-day projects, members, Assignments, datasets, toolkit resources, and Action assignments. Editors can annotate accessible pages, complete their page Tasks, search, and export, subject to locks. Workspace settings can separately allow editors to change page names, descriptions, or tags.

Project/default-resource management and annotation access are separate capabilities. A global curator still needs accepted membership of someone else's workspace. Global administrators have broader instance administration controls; normal workspace membership does not grant those controls.

Use **Workspace Settings → Members** for invitations and member roles, **Requests** for transfers, and **Actions** for workspace processor activation. The available controls follow your role. Use [Account settings](/user-guide/account-and-notifications) for your own invitations and notifications.
