# Troubleshooting your work

Start with the symptom below. Check the selected workspace, the exact error message, and **Jobs** before retrying a long operation. Deployment operators have a separate [technical troubleshooting reference](/troubleshooting/common-issues).

## A project or control is missing

| Symptom | Check | Next step |
| --- | --- | --- |
| A team project is missing | Selected workspace and accepted invitation. | Switch workspace or accept the invitation in Settings. |
| New Project, upload, or resource editing is unavailable | Workspace role. | Ask a workspace curator; editors focus on annotation/review. |
| Team workspace creation is unavailable | Global curator permission. | Ask a global administrator. |
| An operation is visible but rejected | Project/page lock, edit access, quota, and current server message. | Resolve the stated constraint; role alone does not remove a lock. |
| An Action is missing | Workspace activation, project assignment, purpose/target and editor permission. | Ask the curator to check assignment; the administrator manages the definition. |

## An upload or import did not produce the expected page

Open **Jobs** and inspect whether the operation is queued, running, failed, or waiting for conflict resolution. A completed transfer of file bytes does not necessarily mean page processing is complete.

- **Wrong pairing:** inspect page names and file variants before editing. Matching source files must resolve to the intended page.
- **PDF import:** complete its required prefix/preflight step and inspect processing results.
- **IIIF import:** check the preview, selected canvases, conflicts, and failed-canvas details. **Retry Failed** requeues failed canvases. Only one queued/active IIIF import is allowed per project.
- **Quota exceeded:** delete unneeded material or ask an administrator to review usage/quota. Repeated upload attempts do not make space.
- **Package rejected:** check descriptors, declared paths, schema, and the review details. Extracted package edits must update the JSON manifest/descriptors.

See [Projects](/user-guide/projects#add-material) for import behavior and conflict choices.

## The editor is read-only or saving fails

1. Check whether another person holds edit access. Request a handover rather than opening another editing session.
2. Check whether the page is Done, the project is locked, or an Action has reserved the scope. Reopen the page state or wait for the job when permitted.
3. Read the save error before navigating away. Keep the page open while resolving a temporary connection problem.
4. Confirm a successful save before leaving or running an Action.

Use [Collaboration and history](/user-guide/history-and-collaboration) for takeover choices and recovery. Raw XML editing also validates against supported PAGE schemas; invalid XML must be fixed before saving.

## Text, lines, or search results seem missing

- Confirm the page has XML with textlines and transcription. Uploading images and importing IIIF canvases do not run recognition automatically.
- Check image selection separately from transcription variant/index selection.
- Clear text/confidence/variant filters. An active confidence filter excludes variants without usable confidence.
- Save the page and allow its indexing status to refresh. Workspace search uses indexed content.
- Enter at least two characters in workspace search; try **Exact** and **Fuzzy** to understand the matching behavior.

If saved content remains absent, give the administrator the project/page and indexing status. Administrators can inspect or rebuild the index. See [Text review](/user-guide/text-review) and [Workspace search](/user-guide/workspace-search).

## An export is empty or omits pages

Confirm the saved annotation contains transcription for a text export. Check output scope, text level, selected variants, and reading order. For PDFs, pages lacking the chosen image variant are omitted when fallback is disabled. Try the correct variant or enable **Fallback image**, then verify the output page count.

Use a [LAREX package](/user-guide/exports-and-sharing) when you need editable structure rather than a converted reading copy.

## A dataset cannot be exported or released

Run **Validate** and inspect each broken item. A live link depends on its selected source files and workspace; moving/deleting them can break it. A copy depends on its stored copy files. Repair the source/selection where possible, or remove and re-add the intended material. Ask the administrator about missing stored files.

Split percentages are targets. Copied assignments are preserved, and whole-project grouping can deviate from exact sizes. Review split counts and warnings before releasing. See [Datasets](/user-guide/datasets).

## An Action is queued or failed

Inspect the run details, target selection, parameters, and reported error. Queued can mean the processor's concurrency limit is occupied. Saved XML and selected image variants must exist for processors that require them. Retry only after checking the failure; cancellation and retry do not undo results already accepted.

Use [Running Actions](/user-guide/larex-actions) and [Run reports](/actions/run-reports). Escalate processor connectivity and authentication errors to your administrator.

## Report an unresolved problem

Include the operation, project/page or run identifier, approximate time, exact error text, and a short description of what you expected. For an import, include the input format and failing step. Share a small example only through your team's approved support channel. Never include sign-in tokens or release share secrets.
