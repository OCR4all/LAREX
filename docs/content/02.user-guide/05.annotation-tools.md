Annotation tools edit the PAGE XML structures shown on the canvas. Use them to create and correct regions, textlines, baselines, reading order, and relations.

## Choose The Right Mode

| Work | Use |
| --- | --- |
| Create or reshape layout areas | Layout → Hierarchy |
| Focus on textline geometry | Layout → Text lines |
| Focus on baselines | Layout → Baselines |
| Focus on word geometry | Layout → Words |
| Focus on glyph geometry | Layout → Glyphs |
| Edit the page Border and PrintSpace | Layout → Page frame |
| Correct text on the page image | Text → Canvas |
| Search, sort, and review textlines | Text → List |
| Read continuous transcription beside the page | Text → Full text |

Choose the complete mode and view from the grouped toolbar selector before starting a tool-heavy task. It keeps the canvas and sidebars focused on the information you need.

## Draw Shapes

LAREX supports polygon and rectangle drawing where the PAGE element type allows it.

The creation tool button shows the active or last-used tool with a short type tag, such as **Line** or **Word**. Click it to draw that element again, or open its menu to pick another element type and shape. The menu groups tools by element type and explains why a type is unavailable, for example when a glyph needs a selected word first.

Basic flow:

1. Choose the drawing tool.
2. Select the parent element when needed: a text region for textlines, a textline for words, or a word for glyphs. In the Text lines, Words, Glyphs, and Baselines views, LAREX picks the parent the new shape overlaps, or creates the missing parents for you.
3. Draw on the canvas.
4. Double-click to finish polygon or polyline tools.
5. Save the page when the annotation is correct.

Use rectangles for fast regular shapes and polygons for irregular historical layouts.

## Border And PrintSpace

PAGE XML stores two page-level outlines besides the layout hierarchy: the **Border**, which marks the page area of the scan, and the **PrintSpace**, which marks the printed area. A page has at most one of each.

Border and PrintSpace are never filled like regions. They are drawn as plain outlines (Border in cyan, PrintSpace in green), and hovering one makes its line thicker. In the Hierarchy view they appear faded and cannot be selected on the canvas, so they never get in the way of region work. Turn off **Show Border & Print Space in Hierarchy** in the editor settings to hide them there. Other layout views never show them. Switch to **Layout → Page frame** to edit them. In that view, Border and PrintSpace are the only selectable shapes, regions are drawn as dashed context, and everything outside each outline is dimmed so the framed area stands out.

- Draw a Border or PrintSpace with the **Border** or **Print space** entry of the creation tool menu. Picking either tool switches to the Page frame view. While you draw, everything outside the new outline is dimmed. Drawing one while the page already has it replaces the existing outline. A rectangle finished without moving the pointer is discarded.
- Drag nodes, move the whole outline in move mode, or use **Shape Tools** from the context menu as with any polygon.
- Delete the selected outline with `Delete`.

Both outlines are also listed at the top of the structure panel. Selecting one there switches to the Page frame view.

## Edit Existing Shapes

Select an element on the canvas or in the structure panel. Depending on the element, you can move vertices, reshape polygons, adjust baselines, update metadata, or change labels.

The structure panel is useful when overlapping elements make direct canvas selection difficult.

### Select And Delete Polygon Nodes

1. Select the polygon.
2. Drag a rectangle across the nodes you want to remove. Start the drag away from the polygon's handles, or the drag moves a node instead. Hold `Shift` while dragging to add nodes to the current selection.
3. Press `Delete`.

The polygon must keep at least 3 nodes, and its edges must not cross after the deletion. Otherwise LAREX keeps the shape and shows **Cannot delete selected nodes**. While nodes are selected, `Delete` never removes the whole polygon, even when you hold the key down. Undo restores the deleted nodes.

### Constrain to Parent

Select one or more polygons, open the context menu, and choose **Shape Tools → Constrain to Parent**. This intersects each selected shape with its parent polygon and removes the parts outside. It also works while **Parent Bounds** is disabled. Top-level regions have no parent to constrain to.

If an imported shape already extends outside its parent, **Parent Bounds** can block node dragging. The error message offers a **Constrain to Parent** button to repair the shape directly.

Disconnected intersections become separate shapes. Shapes entirely outside their parent are removed. Children and baselines are clipped with their container, and the complete operation can be undone or redone.

## Cut And Merge

Cut tools split existing layout structures. Merge combines compatible structures when an earlier split or processor result created too many elements.

Before using destructive geometry tools:

- zoom in enough to verify the target
- confirm the selected element in the structure panel
- save after a coherent correction, not after every click

## Tables

A PAGE `TableRegion` holds its cells as nested regions. When the table has a grid, the grid decides where the cells and the table outline are. LAREX redraws cell outlines from the grid after every table edit.

### Create a table

- Draw a region and set its type to **TableRegion**. The **Create Table Grid** panel opens. Choose rows, columns and header rows; the canvas previews the grid lines.
- Right-click an existing region and choose **Convert to Table...**. For text regions, you can move the existing text lines into the new cells.
- Select several regions with the same parent and choose **Build Table from Selection**. LAREX works out rows, columns and spans from the region positions.
- For a table that has cells but no grid, choose **Create Grid from Cells**.
- **Assign Text Lines to Cells** moves every text line inside the table into the cell that contains its centre.

### Change the structure

Right-click a cell and open the **Table** menu:

- **Split Row** and **Split Column** cut through the middle of the cell's row or column. Drag the new grid line afterwards to adjust it.
- **Merge Row with Next** and **Merge Column with Next** remove the line between them. The cells on both sides must line up.
- **Split Cell** turns a spanning cell back into single cells.
- **Mark as Header Row** sets or clears the header flag for every cell in the row.
- **Delete Row** and **Delete Column** remove the cells and their text lines. LAREX asks for confirmation when text lines would be deleted. Deleting an outer row or column shrinks the table. Deleting an inner one widens the row above or the column to the left.

Select cells of one table that form a rectangle and choose **Merge Cells** to join them. Text lines from all merged cells are kept.

### Edit the grid geometry

Select a cell or the table and drag a node that lies on the grid. All cells sharing that point follow. Click a cell edge to add a point to the shared grid line, and delete such points with `Delete`. Grid corners cannot be deleted; merge or delete rows and columns instead.

### Limits

- Grid editing only applies to tables whose grid can be read. If an imported grid stores `AddPoints` as free text, LAREX keeps it unchanged, and the table menu offers no structure edits.
- Cell outlines that do not match the grid, for example in imported files, are edited as independent shapes until the next table edit redraws them from the grid. The same happens to the table outline.

## Reading Order And Relations

Reading order describes sequence. Relations describe explicit links between PAGE elements.

Use the reading order panel when text flow matters for downstream OCR/HTR, exports, or review. Use the relations panel when your project needs semantic links between elements, such as source/target region relationships.

## Set reading order

1. Open the **Reading Order** panel in layout mode.
2. Inspect the current order and the **Available** list of regions not yet included.
3. Add the intended regions, then drag entries into the reading sequence.
4. Select related entries and use **Ordered** for a sequence or **Unordered** for a group with no defined sequence. Expand groups to inspect their contents; dissolve a group when its grouping is no longer useful.
5. Turn on the reading-order overlay and inspect arrows, numbers, group bounds, and labels against the page.
6. Save and check the result before relying on flattened text exports.

Canvas selection and reading-order list selection have different gestures. Within the order list, Ctrl/Cmd-click toggles items and Shift-click selects a range. Removing a reference from the order does not mean deleting that region's geometry.

## Create a region relation

1. Open **Relations** and start a relation draft.
2. Choose its type and source/target regions, or use **Pick On Canvas** to select endpoints.
3. Leave the relation ID empty to generate one, or supply the intended ID.
4. Add optional labels, custom information, or comments where needed, then choose **Create Now**.
5. Inspect the relation overlay, save, and verify that the endpoints identify the intended regions.

A relation records a link between regions. It does not replace the page's reading-order sequence.

## Edit metadata at the correct level

The **Metadata** panel changes with the selected element. Clear the selection for document/page metadata; select a region or textline for its fields. Review the element identifier before applying edits.

Available fields depend on PAGE element type. They include reading direction/orientation, comments, language and script information, label groups, alternative images, and typed user attributes. A label group can carry external model/ID information; a user attribute has a name, optional description/type, and value.

Apply the metadata edit and save the page. Use the raw XML editor for XML inspection and schema validation, and [version comparison](/user-guide/history-and-collaboration#compare-and-restore-a-version) when reviewing an earlier saved state.

## Actions And Targeted Processing

The Action wand can use selected page structures as processor targets. Region and textline Actions are useful when a processor should re-run on only part of a page.

Targeted Actions still dispatch full page files. The processor receives selected region or textline IDs and returns normal PAGE XML. LAREX imports only the selected target scope.
