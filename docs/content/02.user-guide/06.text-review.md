Use text mode after a page has textlines and transcription, either imported, entered manually, or produced by an Action. Geometry and text are separate: fix a wrong line boundary in layout mode, then review its text.

**Before you start:** open the intended image variant and check the project's ground-truth and recognition indices. These select transcription alternatives, not images. Save any important work before running batch operations or Actions.

## Choose a text view

Open the toolbar's mode-and-view selector.

| View | Default key | Best for |
| --- | --- | --- |
| Text · Canvas | `Ctrl/Cmd+6` | Correcting a line with its position on the source image in view. |
| Text · List | `Ctrl/Cmd+7` | Reviewing line cutouts, searching, sorting, and filtering textlines. |
| Text · Full text | `Ctrl/Cmd+8` | Reading and correcting the page transcription beside the page canvas. |

The layout views remain available with `Ctrl/Cmd+1`–`Ctrl/Cmd+5`. These are defaults; use `?` to inspect or customize your active shortcuts.

The default region sequence in List and Full text views, and line navigation in Canvas view, follows the PAGE XML reading order when present, including nested groups. Text in regions omitted from the reading order remains available after the referenced regions. Without a reading order, each view uses its fallback ordering.

## Review a page line by line

1. Open **Text · List** and choose the text alternatives you need to see.
2. Compare each line's transcription with the corresponding image cutout.
3. Correct the ground-truth text, preserving the project's transcription conventions. If a line has no GT yet, create it first (see [Create ground truth](#create-ground-truth)).
4. Use the dictionary, codec, or diff panels when the project assigns those resources.
5. Save, then complete the associated page Task when your review is finished.

The list's **Filter textlines** popover combines several filters:

| Filter | Options |
| --- | --- |
| Ground truth | All, With GT, Without GT |
| Comments | All, With, Without |
| Diff | All, Mismatches, No mismatches |
| Additional filters | Empty transcriptions, Dictionary mismatches (needs a project dictionary), and the current text search |

The same popover holds the index, confidence-range, and variant-visibility settings. A confidence filter excludes variants without a usable confidence value; a missing confidence does not mean zero confidence. If a line disappears unexpectedly, choose **Reset** in the popover and check variant selection.

## Create ground truth

Only the variant at the project's GT index is editable. Recognition variants are read-only, and variants at any other index are disabled.

| Line state | Control | Result |
| --- | --- | --- |
| No text variants | **Add** | Adds an empty variant at the lowest free index. |
| Recognition text, no GT | **Create GT** | Copies the first non-empty recognition variant to the GT index. |
| Already has GT | — | **Add** and **Create GT** are hidden. Edit the GT field directly. |

To move a variant to another index, select the index number left of its text field, then enter a number or check **Unindexed**. If another variant already uses that index, saving swaps the two indices. Use this when **Add** created index `0` but the project's **Default GT Index** is different.

Navigating, filtering, or changing the GT index does not create GT. In **Text · Canvas**, GT is created only when you type into the selected line or choose **Copy to GT**.

Recognition confidence is a processor estimate, not proof of correctness. A dictionary hit likewise confirms only membership in that dictionary.

## Read in Full text view

Choose **Text · Full text** to show the page canvas and continuous transcription side by side. Drag the divider to resize the panes, or focus it and use the arrow keys. Selecting textlines connects the transcription with their location on the canvas.

This view edits the page's existing textline transcription. It is useful for reading context across lines; switch back to layout mode when lines or region structure need correction.

The comments control shows textline comment affordances. Open a line's comment control, enter the review note, and save it. Save the page to persist annotation changes. Textline comments belong to the annotation; assignment discussion belongs in the Assignment's **Comments** tab.

## Understand text alternatives

PAGE XML can hold several `TextEquiv` alternatives, each with an optional index and confidence. A project can identify one index as ground truth and others as recognition indices.

Before comparing or correcting alternatives:

- Check which index represents your team's accepted transcription.
- Check the selected alternatives and filters when text seems missing.
- Keep recognition output distinct when your workflow needs before/after comparisons.
- Save corrections before exporting, searching, or building a dataset release.

Changing index settings changes how text is interpreted by tools; it is not a recognition operation.

## Use review resources deliberately

| Resource | Helps you find | Next action |
| --- | --- | --- |
| [Codec](/user-guide/toolkit/codecs) | Characters outside the accepted inventory. | Correct the text or ask a curator to extend the inventory. |
| [Dictionary](/user-guide/toolkit/dictionaries) | Unexpected words and possible replacements. | Compare the source, then correct or accept the token. |
| [Virtual keyboard](/user-guide/toolkit/virtual-keyboard) | Characters difficult to type. | Insert the intended character in the active text field. |
| [Normalization profile](/user-guide/toolkit/normalization) | Repeatable textual changes. | Preview changes and scope before applying them. |
| [Validation ruleset](/user-guide/toolkit/validation-rulesets) | Text matching configured regex patterns. | Inspect samples and affected pages; resolve or document the finding. |

Normalization can change saved text when you choose Apply. A preview does not persist those changes. Review resource definitions with your curator before using them for a large batch.

## Finish and verify

Save the page and confirm success. For assignment work, use the editor's save-and-complete flow to persist annotations and complete the relevant Task. A page's workflow state and an Assignment's status are separate; see [Assignments and page Tasks](/user-guide/tasks). If the work needs a second pair of eyes, [submit the page for review](/user-guide/tasks#page-states-and-review).

Use [workspace search](/user-guide/workspace-search) to find recurring errors elsewhere, or [version comparison](/user-guide/history-and-collaboration#compare-and-restore-a-version) to inspect a saved checkpoint.
