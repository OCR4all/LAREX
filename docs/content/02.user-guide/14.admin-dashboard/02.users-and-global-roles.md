# Users and Global Roles

Open **Admin -> Users** to manage accounts across the LAREX instance. The page lists normal users, hides service accounts by default, and provides status filters for active, pending setup, and disabled users.

## Find Users

Use the search field to match username, email, first name, or last name. Use the status filter to narrow the table to:

| Status | Meaning |
| --- | --- |
| Active | The account is enabled and ready for use. |
| Pending Setup | LAREX created the account and the user still needs to complete setup. |
| Disabled | The account cannot sign in until re-enabled. |
| Service Account | A technical account. These accounts are not managed from the normal user controls. |

The table shows account identity source, onboarding state, creation date, last login, and row actions. Open **Details** to inspect the full account profile.

**Last login** records the most recent successful sign-in to this LAREX instance, including sign-ins through an existing Keycloak SSO session. It is not updated by token refreshes or normal application use. **Unknown** means no login has been recorded since tracking was enabled; it does not mean the user has never logged in. Service accounts show **N/A**. Only the latest timestamp is retained, without a login history, IP addresses, or device information. If recording fails, sign-in still succeeds and the previous timestamp remains.

Click the **Last login** column header to sort from oldest to newest; click again for newest to oldest. Unknown dates appear last in both directions. **Logged in before** includes recorded logins strictly before midnight at the start of the selected date in your local timezone; unknown dates are excluded. Sorting and filtering apply across all users before pagination, and can be combined with search and status filters. Clear filters removes the date cutoff as well.

Use this date to review potentially inactive accounts before disabling them. Users with an existing session may still be active without a recent login. The deployment operator should describe this account-management purpose and its retention policy in the privacy notice.

## Create A Local User

1. Open **Admin -> Users**.
2. Select **Create User**.
3. Enter username and email.
4. Optionally enter first and last name.
5. Submit the form.

LAREX creates the user and sends a setup email. Usernames and email addresses must be unique. Usernames beginning with `service-account-` are reserved.

If **Create User** is not available, the deployment uses LDAP-managed identities. Create and update users in the external identity provider instead.

## Manage Account State

Use row actions to manage lifecycle state:

| Action | Use it when |
| --- | --- |
| Resend Setup | A pending user did not receive or can no longer use the setup email. |
| Disable | A local user should no longer be able to sign in. |
| Enable | A disabled local user should regain access. |

LAREX prevents disabling your own current account. LDAP-managed users and service accounts cannot be enabled or disabled from this page.

## Review User Details

The details panel shows:

- display name, email or username, avatar, user ID, and verification state
- identity source: local, LDAP, or service account
- whether the account is externally managed
- created timestamp and last login
- current global admin and global curator flags
- recent administrative audit events for the user

Use the copy button next to **User ID** when you need to correlate events, logs, or support requests.

## Manage Global Curator

`GLOBAL_CURATOR` allows a user to create team workspaces. Managing another team workspace still requires the appropriate accepted membership; it does not grant access to every workspace. Open a user's details panel, then select **Grant Curator** or **Revoke Curator**.

A reason is required. LAREX stores the reason in the user audit trail. Role changes may require token refresh or re-login before they are visible in the user's session.

`GLOBAL_ADMIN` is visible in the details panel, but normal dashboard controls only grant or revoke `GLOBAL_CURATOR`. Manage global admin bootstrap and realm role assignment through the configured identity provider.

## Audit Events

The details panel records administrative actions such as user creation, setup email resend, enable/disable, and global curator grants or revocations. Use the audit list to answer:

- who changed the account
- what action was attempted
- whether it succeeded
- what reason or metadata was recorded

## Identity Provider Boundaries

When a user is LDAP-managed, lifecycle changes must happen in the directory or identity provider. LAREX still shows the account for lookup, auditing, and role visibility, but does not own profile fields or account enablement.

Profile avatars are the exception to that identity boundary: generated avatars and uploaded profile
images are owned by LAREX. LDAP-managed users can upload or remove their own image without changing
their identity-provider account.
