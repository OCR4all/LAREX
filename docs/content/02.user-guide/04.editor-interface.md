The editor is where page images and PAGE XML become reviewable, editable project data. It combines page navigation, a canvas, annotation tools, text review, metadata, validation helpers, and processor entry points.

## Image resolution

The editor displays a smaller presentation image by default while keeping annotations in the original image's pixel coordinates. Text-line cutouts use the same coordinate mapping. The toolbar uses an **SD** icon for Preview and an **HD** icon for Full Resolution, with a tooltip showing the active mode (**Preview** or **Full Resolution**) and the mode clicking will switch to. Click it to switch the active canvas between the smaller display image and the full-size original, including large scans. Full Resolution is highlighted while selected, and a spinner indicates loading. Selecting another image returns that canvas to preview mode. Downloads and Actions continue to use originals.

Full-resolution scans may take longer to load and use substantially more memory. Extremely large originals are fitted to the GPU's supported texture dimensions for rendering. Tile-based deep zoom is not yet available.

## Layout

```text
Left sidebar  |  Center tabs and canvas  |  Right sidebar
Project/page  |  page image + overlays   |  structure, metadata,
navigation    |  text and layout modes   |  settings
```

The center area uses tabs for projects and pages. The left sidebar is for navigation and filtering. The right sidebar is for work on the active page.

## Left sidebar

Use the left sidebar to:

- return to the dashboard
- open the command center
- filter page names
- apply advanced page filters
- choose the default image variant
- browse opened projects and pages
- access the user menu

The sidebar can be collapsed and resized.

## Center canvas

The canvas displays the active page image and PAGE XML overlays. In layout mode, it is optimized for region, textline, baseline, reading-order, relation, and metadata work. In text mode, it focuses on transcription review and token-level correction.

Mouse behavior:

| Interaction | Result |
| --- | --- |
| Wheel | Zoom |
| Drag empty space | Pan when no shape edit is active |
| Click | Select or edit according to the active tool |
| Shift-click in the select tool | Add an element to the selection, or remove it if already selected |
| Shift-drag in the select tool | Add elements enclosed by the selection rectangle |
| Double-click | Finish polygon or polyline drawing |

Wheel zoom follows the scroll distance, including fine trackpad movements, and stays anchored to the point under the cursor. Trackpad pinch gestures also zoom. Dragging empty space pans directly with the pointer.

Shift-click works for regions, textlines, and baselines in their respective layout views. It changes the selection without focusing the clicked element, so other elements at the same level stay visible. Shift-clicking empty space keeps the current selection. With a table cell selected, Shift-click adds other cells of the same table. While drawing, hold Shift and drag to pan.

## Collaboration and edit access

One user holds edit access to a page at a time. Other users can request access;
the current editor can grant the request, and users with the required permission
can force a takeover.

**Force takeover** lets you choose **Save and take over** to persist the current
live annotations before transferring edit access, or **Discard and take over** to
reload the last saved version. If saving fails, edit access stays with the current
editor. Saving requires synchronized live annotations.

A takeover starts a fresh timeout period. The editor keeps renewing access while
the page remains open and renewal requests can reach the server. A temporary
interruption of live collaboration updates does not by itself release access.
Reloading annotations or switching between
layout and text views does not release access. Access can transfer when the editor
grants a request, another user forces a takeover, or the editor leaves the page.
If renewal stops, the lease can time out so another user can edit.

## Toolbar

The toolbar can float or dock to the top, bottom, left, or right. Change this from **Toolbar position** in the toolbar settings menu at the end of the toolbar.

The combined mode-and-view selector is at the end of the toolbar. Its trigger shows the complete active state, such as **Layout · Hierarchy** or **Text · Canvas**. Open it to choose from two groups:

- Layout views: **Hierarchy**, **Text lines**, **Baselines**, **Words**, **Glyphs**, and **Page frame**
- Text views: **Canvas** for focused correction on the page image and **List** for searchable, sortable textline review, and **Full text** for a continuous transcription beside the canvas

With the default shortcuts, `Ctrl/Cmd+1`–`Ctrl/Cmd+5` select Layout · Hierarchy, Text lines, Baselines, Words, and Glyphs, `Ctrl/Cmd+6`–`Ctrl/Cmd+8` select Text · Canvas, List, and Full text, and `Ctrl/Cmd+Alt+P` selects Layout · Page frame. Open `?` to customize bindings.

Main tool groups:

- select and move
- draw regions, textlines, words, glyphs, baselines, and the page Border and PrintSpace from one creation tool menu
- cut, merge, and edit shapes
- choose the active mode and view from one grouped selector
- undo, redo, and history
- open keyboard shortcuts
- pick an Action target with the wand tool

Use `?` to open the shortcut dialog.

## Right sidebar

The right sidebar contains the working panels for the active page.

Layout mode panels:

- structure
- table, while a table, a cell, or a text line in a cell is selected
- reading order
- relations
- metadata
- heatmap
- settings

Text mode panels:

- metadata
- settings
- virtual keyboard
- codec
- dictionary
- diff, called **Text Variants** in Full text

### Page actions

The menu next to **Save** holds the actions for the active page:

| Action | What it does |
| --- | --- |
| **Version History** | Compare or restore saved versions of the annotation. |
| **View/Edit XML** | Open the raw PAGE XML. |
| **Edit Page Metadata** | Change the page name, description, or tags. |
| **Page state** and **Review history** | Change the page's workflow state or see earlier changes. |
| **Run Action** | Run a LAREX Action on the whole page. |
| **Add to Dataset** | Add the page to an existing or new dataset. Needs the permission to manage projects. |
| **Export Page** | Convert the page to another format or PAGE XML version. See [Exports and sharing](/user-guide/exports-and-sharing#export-a-project-or-page). |
| **Download** | Get the stored annotation or an image variant without conversion. |
| **Copy** | Copy the page text, a link to the page, or the page ID. |
| **Save + Complete** | Save and complete your open Tasks for the page. |

**Run Action**, **Add to Dataset**, **Export Page**, and the **Copy** actions are also listed under **Active Page** in the command palette (`Ctrl+K` or `Cmd+K`).

**Run Action**, **Add to Dataset**, and **Export Page** work on the saved annotation. If you can edit the page and it has unsaved changes, LAREX asks you to save first. If you can't edit the page right now, for example because someone else is editing it, **Add to Dataset** and **Export Page** use the last saved state. The three actions are not available for frozen dataset copies, because they read the page from its project.

**Copy Page Text** copies the current text lines, including unsaved changes. Lines follow the reading order. Lines without GT fall back to other text [the same way converted exports do](/user-guide/exports-and-sharing#which-transcription-a-converted-export-uses), and empty lines are left out.

In Settings, **Vertex Size** controls polygon vertices and baseline handles independently of **Line Width**. Choose Tiny, Small, Normal, Large, or Extra Large. Normal preserves the original sizes. Hover and preview handles keep their relative sizes, and zoom behavior stays the same. Your choice is saved with your editor preferences.

## Save before processing

LAREX Actions process saved PAGE XML. If you select a page, region, or textline in the editor and there are unsaved changes, LAREX asks whether to save before dispatching the Action. The same applies when you export the page or add it to a dataset.

If saving fails, the Action is not started. This prevents processors from reading stale or inconsistent PAGE XML.

## Pick Action targets

Use the wand tool or context menu to run processors on editor targets:

| Target | What the processor receives |
| --- | --- |
| Page | Full selected page scope. |
| Region | Full page files plus selected region IDs. |
| Textline | Full page files plus selected textline IDs. |

Processors receive full page images/XML according to their Action definition. The target metadata tells the processor which region or textline the user selected.
