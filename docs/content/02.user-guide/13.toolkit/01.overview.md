# Toolkit

Toolkit resources define the shared conventions a workspace or project uses during annotation, text correction, search, and review. Curators configure them once, then assign them as workspace presets or project settings so users do not have to make the same choices repeatedly.

## Resources

| Resource | Use it for |
| --- | --- |
| [Tag Sets](/user-guide/toolkit/tag-sets) | Controlled project and page classification. |
| [Label Sets](/user-guide/toolkit/label-sets) | Annotation labels exposed in the editor. |
| [Virtual Keyboard](/user-guide/toolkit/virtual-keyboard) | Project-specific characters during text correction. |
| [Codecs](/user-guide/toolkit/codecs) | Accepted character inventories and coverage checks. |
| [Dictionaries](/user-guide/toolkit/dictionaries) | Token review, suggestions, and accepted word lists. |
| [Normalization](/user-guide/toolkit/normalization) | Previewed text transformations for comparison or explicit application to saved transcription. |
| [Validation Rulesets](/user-guide/toolkit/validation-rulesets) | Regex matches in transcription text. |

## How Toolkit Resources Fit Together

Use toolkit resources together:

- Tag sets organize projects and pages.
- Label sets guide layout annotation.
- Virtual keyboards make transcription input faster and more consistent.
- Dictionaries flag unexpected tokens.
- Normalization profiles make comparisons more stable.
- Validation rulesets turn project policy into reviewable checks.

Assign supported common defaults at the workspace level when most projects should start with the same conventions. Set a virtual keyboard in project settings; the workspace-default form does not offer a keyboard default. Override them at the project level when a project needs different rules.

## Export, import, and share resources

Toolkit resource menus offer package export and sharing where your role permits it. Import a toolkit package to recreate a resource in another workspace or instance, or request a copy/move through the sharing flow. Review naming and content conflicts before replacing an existing resource, because other projects may already use it.

Assigning a resource to a project uses that workspace resource. Updating the definition can affect every project referencing it. Changing a label definition does not automatically relabel existing PAGE XML, and saving a normalization profile does not apply a rewrite by itself.

Workspace default changes offer future-only, fill-missing, and replace-all propagation. See [Workspace presets](/user-guide/workspace-library#workspace-presets) before applying defaults to existing projects.
