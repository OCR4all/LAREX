# Account and notifications

Open **Settings** from your user menu. Account settings apply to you; **Workspace Settings** controls the selected workspace and requires the appropriate workspace role.

## Profile and appearance

Use **Profile** to manage the account details offered by your deployment and upload or remove a profile picture. LAREX accepts JPEG, PNG, and WebP profile images up to 5 MB, crops them to a square, and stores the result in application-managed storage.

**Appearance** controls available display preferences. Generated avatar styles are an instance setting; ask a global administrator to change the default style for users without a custom image.

Editor shortcuts have a separate customization surface: open `?` in the editor. See [Keyboard shortcuts](/user-guide/keyboard-shortcuts).

## Accept an invitation

1. Open **Settings → Invitations**.
2. Inspect the workspace and offered role.
3. Accept to join, or decline if the invitation is not intended for you.
4. Select the workspace from the switcher after joining.

Workspace membership is separate from your global role. If you can sign in but cannot see a team project, confirm that you accepted its workspace invitation and selected that workspace.

## Review transfers

**Settings → Transfers** shows personal incoming/outgoing transfer activity. Workspace curators also handle workspace transfer requests in **Workspace Settings → Requests**.

Inspect the resource/project and whether the request is a copy or a move before accepting it. Follow any naming-conflict review the interface presents. Pending outgoing requests can be cancelled; accepting a move changes where the working content belongs.

See [Exports and sharing](/user-guide/exports-and-sharing#transfer-work-between-workspaces) for the distinction between workspace transfers and externally shared releases.

## Choose notifications

Open **Settings → Notifications**. The preferences table provides per-event controls for:

| Channel | Requirement |
| --- | --- |
| In-app | Read events inside LAREX's notification interface. |
| Desktop | Your browser must support notifications and you must grant permission. |
| Email | Your instance must have working email delivery. |

Enable browser permission in the desktop-notification section. If the browser reports **Blocked**, change permission in its site settings before trying again. A desktop toggle alone cannot override a blocked browser permission.

Enable the event/channel combinations that help you follow assignments, invitations, and other work. If email does not arrive, check your preference and spam folder, then ask the administrator to inspect delivery. Use **Jobs** for background-operation progress; notifications are not a substitute for checking a failed upload or run.

## Password and security

**Settings → Security** links to Keycloak's self-service portal for password changes and any enabled account-deletion flow. Available controls depend on the configured identity provider. For LDAP or organization-managed credentials, follow your organization's account process.

Account deletion is irreversible. Check ownership and ongoing team work with your administrator before using that flow. See [Users and global roles](/user-guide/admin-dashboard/users-and-global-roles) for administrator account controls.
