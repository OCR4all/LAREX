A PAGE `TableRegion` holds its cells as nested regions. When the table has a grid, the grid decides where the cells and the table outline are. LAREX redraws cell outlines from the grid after every table edit.

## Create a table

- Draw a region and set its type to **TableRegion**. The **Create Table Grid** panel opens. Choose rows, columns and header rows; the canvas previews the grid lines.
- Right-click an existing region and choose **Convert to Table...**. For text regions, you can move the existing text lines into the new cells.
- Select several regions with the same parent and choose **Build Table from Selection**. LAREX works out rows, columns and spans from the region positions.
- For a table that has cells but no grid, choose **Create Grid from Cells**.
- **Assign Text Lines to Cells** moves every text line inside the table into the cell that contains its centre.

## Change the structure

Right-click a cell and open the **Table** menu:

- **Split Row** and **Split Column** cut through the middle of the cell's row or column. Drag the new grid line afterwards to adjust it.
- **Merge Row with Next** and **Merge Column with Next** remove the line between them. The cells on both sides must line up.
- **Split Cell** turns a spanning cell back into single cells.
- **Mark as Header Row** sets or clears the header flag for every cell in the row.
- **Delete Row** and **Delete Column** remove the cells and their text lines. When text lines are deleted, a notification offers **Undo**. Deleting an outer row or column shrinks the table. Deleting an inner one widens the row above or the column to the left.

The same menu also holds the actions for the whole table: **Repair Table**, **Assign Text Lines to Cells**, **Generate Reading Order** and **Export Table**. They are also in the table's own context menu when you right-click it with nothing selected.

To merge cells, click one cell, `Shift`-click the other cells of the same table, then right-click one of them and choose **Merge Cells**. The cells must form a rectangle. Text lines from all merged cells are kept.

## Edit the grid geometry

Select a cell or the table and drag a node that lies on the grid. All cells sharing that point follow. Click a cell edge to add a point to the shared grid line, and delete such points with `Delete`. Grid corners cannot be deleted; merge or delete rows and columns instead.

Hold `Alt`/`Option` and drag a cell edge to move its whole row or column line. Row lines move up and down, column lines left and right. A line cannot be moved past its neighbours.

Moving the table in move mode takes its cells, their text lines and the grid along.

After every grid or structure edit, text lines whose centre now lies in another cell move into that cell.

## Table text and reading order

Select a table, a cell or a text line inside a cell, then open the **Table** panel in the right sidebar. It shows the table layout as a small map with spans and header rows; hatched cells have no text lines. Cells outlined in amber hold text lines that cross the cell border. Click a cell to select it on the canvas.

With a cell selected, `Alt`/`Option` and the arrow keys select the neighbouring cell.

Full text mode lays out tables as tables, at the position of the table's first line in reading order. Each cell lists its text lines with the same editing, comments and checks as any other line. `Tab` and `Enter` move through the lines cell by cell, row by row.

To order the cells, right-click a cell and choose **Table → Generate Reading Order → Row by Row** or **Column by Column**, or use **Reading order** in the Table panel. LAREX replaces the table's entry in the reading order with an ordered group of its cells, or adds that group at the end, and removes other references to the cells.

## Inspect and repair tables

The **Table** panel lists the table's size, cell count, header rows and whether it has a grid. Below the map it shows the selected cell: its position, span, text lines and a **Header cell** checkbox. Rows, columns, the grid and cell roles are edited here and through the table menus, not in the **Metadata** panel.

LAREX checks every table on the page. When it finds problems, the status bar shows a **table problems** button; the Table panel lists the same problems for the selected table. Click a problem to select the element it concerns.

**Repair table**, in the problem list or the **Table** menu, fixes what it safely can:

- cell spans below 1 or reaching past the table
- regions in the table without a cell role, which get the free grid cell containing their centre
- table positions no cell covers, which get new empty cells
- cell and table outlines that do not match the grid
- the rows and columns attributes
- text lines whose centre lies in another cell

Overlapping cells, cells outside the table and broken grids need manual fixing. Text lines that only stick out of their cell stay where they are; adjust the grid or the line. Undo reverts the whole repair.

The server runs the same structural checks whenever it writes PAGE XML, for example for processor results. It records problems in its log but still saves the file.

## Limits

- Grid editing only applies to tables whose grid can be read. If an imported grid stores `AddPoints` as free text, LAREX keeps it unchanged, and the table menu offers no structure edits.
- Cell outlines that do not match the grid, for example in imported files, are edited as independent shapes until the next table edit redraws them from the grid. The same happens to the table outline.

## Export tables

Right-click a cell and choose **Table → Export Table → CSV** or **HTML** to download that table. Each cell holds the text of its text lines, using the project's default transcription. In CSV, a spanning cell's text sits in its top left position and the positions it covers stay empty. HTML keeps spans and marks header cells.

To export the tables of many pages, use the project export with the **Tables** spreadsheet profile:

- **CSV** has one row per cell, with the page, table, cell position, span, header flag and text.
- **XLSX** has an index sheet listing every table, plus one sheet per table laid out as the table, with merged cells for spans and bold header cells.

ALTO has no tables. ALTO exports keep each table as a block of type `TableRegion` with one text block per cell.

## Tables from Actions

Run an Action on a selected table to have a processor fill it, for example with table recognition. When the processor returns the table with cells and a grid, LAREX takes the returned cells, grid, size and outline. Run an Action on a selected cell to replace only that cell's text lines; its position in the table stays. See [Result Import](/actions/result-import#region-targeted-xml).

## Tables and collaboration

Only the person holding a page's edit lock can change its tables, so two people never restructure a table at the same time. Viewers see every table edit as it happens. See [History and Collaboration](/user-guide/history-and-collaboration).
