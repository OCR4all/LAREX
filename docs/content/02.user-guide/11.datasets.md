# Datasets and releases

A dataset collects selected annotation and image files from project pages in the same workspace. Use it to curate ground truth across projects, prepare training/evaluation splits, and publish a reproducible snapshot.

Workspace owners and curators manage dataset contents, settings, splits, and releases. Workspace members can access available datasets and use supported editor/export operations. Annotation access still respects the applicable source or copy permissions.

## 1. Create a dataset and add pages

You can create a dataset from **Datasets**, or select project pages and choose **Add Selected Pages To Dataset**, then **Create new dataset**.

1. Select the target dataset and storage mode.
2. Use **Customize variants** if you need a specific XML annotation or image selection.
3. Choose one XML source per page and the image variants to include. By default, all available image variants are selected.
4. Review the ready, skipped, and blocked counts, then add the pages.

Global image selection applies to inherited rows; disable inheritance on a row to override it. A page without selected images is skipped. A page without an available XML source is blocked from being added through this flow.

**Check:** the dataset's Pages tab contains the intended source pages, modes, and files. Selecting an image variant here does not create new recognition text.

## 2. Choose live links or copies

| Mode | Source changes | Editing from the dataset | Use it for |
| --- | --- | --- | --- |
| Live link (`LINK`) | Uses the selected current source files; removal or transfer can break the link. | Edits the source project's annotation, subject to its locks. | Curation that should follow ongoing project corrections. |
| Frozen copy (`COPY`) | Starts with independent copies of the selected files. | Edits the dataset's own annotation copy, with its own XML history. | A separate working sample that must not change the source. |

“Frozen copy” describes independence from source updates. Its working annotation can still be corrected. A **release** is the immutable delivery artifact.

When opening dataset pages in the editor, inspect the mode and any skipped/read-only messages. PAGE XML is required for visual annotation editing. A stored annotation in another format can be part of dataset material without being openable in that editor.

## 3. Configure splits

Choose **Train / Validation** or **Train / Validation / Test**, set percentages totaling 100, and select an algorithm.

| Algorithm | Behavior and tradeoff |
| --- | --- |
| Random seeded split | Repeatable assignment for the same inputs and seed. Pages from one project can appear in different splits. |
| Group by source project | Keeps the mutable items from each source project together. Whole groups can make exact percentage targets impossible. |
| Stratify by selected tags | Uses selected page tags to balance tagged groups. With no selected tags it falls back to seeded random assignment and reports a warning. |

Save settings, then use **Regenerate Splits** when you want new assignments. You can also change a row's split manually.

Existing copied items retain their split during regeneration; mutable linked items can be reassigned, including manually assigned linked items. Preserved copies can therefore exceed a target percentage or prevent strict project grouping. Check the actual counts and warnings after every regeneration. Switching to the two-way template maps Test assignments to Validation.

For evaluation, select a split policy that avoids overlap between training and held-out material. The grouping option is useful when pages from the same source would otherwise make the evaluation too similar to training data; review preserved copies as well.

## 4. Validate before export

Choose **Validate**. Dataset validation checks whether selected source/copy files and references are available. It reports broken items, reasons, and warnings. It is separate from regex [text validation rulesets](/user-guide/toolkit/validation-rulesets) and does not certify transcription quality.

Resolve broken items before exporting or creating a release; both operations reject a dataset with broken items. For a broken live link, inspect whether the source page, selected XML, or selected image was removed or moved out of the workspace. For a broken copy, ask the administrator to inspect its stored files.

## 5. Export or freeze a release

- **Export Package** builds a package from the dataset's current working state.
- **Create Release** stores a frozen snapshot with a version tag, notes, item count, package checksum, and manifest checksum. Later dataset edits do not update it.

Open the **Releases** tab, create the release, and wait for it to be ready before downloading. Give it a meaningful tag and notes describing curation choices, transcription conventions, and split policy. Keep the downloaded package and checksums with the experiment or delivery record.

A package contains its manifest, selected images/XML, and split lists. Freezing the release makes its bytes reproducible even when the working dataset uses live links.

## 6. Share or reuse the release

Open the release's **Release Share** controls to create an expiring share. Copy its download URL and secret when created; the full secret is not shown again after that response. Anyone holding the secret can download until expiry or revocation. Rotate it to replace the credential, extend its expiry when needed, or revoke it to stop further downloads.

Dataset release sharing exposes the frozen package, not the workspace. Revoking access does not remove copies someone already downloaded.

Use [Training](/actions/training), [Evaluation](/actions/evaluation), or a dataset integration Action to reuse the dataset. Its Actions menu exposes applicable assigned processors. Dataset output retention controls stored Action outputs, not the immutability of an already created release. See [Run reports and outputs](/actions/run-reports).
