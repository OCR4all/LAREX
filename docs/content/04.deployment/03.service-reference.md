# Service Reference

The deployment surface is built from a small set of compose fragments instead of multiple full-stack files.

## Compose Fragments

| File | Responsibility |
|------|----------------|
| `compose.prod.base.yaml` | Shared production runtime services: `postgres`, `app`, `frontend` |
| `compose.prod.auth.bundled-keycloak.yaml` | Adds bundled `keycloak`, `keycloak-postgres`, and bundled-auth wiring |
| `compose.prod.auth.external-keycloak.yaml` | Rewires `app` and `frontend` to an external Keycloak |
| `compose.prod.publish.localhost.yaml` | Publishes frontend on loopback for production |
| `compose.prod.local.yaml` | Adds local Nginx, Mailpit, and `*.localhost` routing |
| `compose.dev.docs.yaml` | Adds self-hosted docs for local dev (`docs.localhost`) |
| `compose.prod.local.docs.yaml` | Adds self-hosted docs for local production-like setup (`docs.localhost`) |
| `compose.prod.docs.yaml` | Adds self-hosted docs for opinionated production (loopback port) |
| `compose.prod.nginx.yaml` | Adds optional bundled Nginx for production |
| `compose.actions.yaml` | Adds official Action processor services through opt-in profiles |

## Service Matrix

| Service | Local dev | Local production-like | Opinionated production | Optional production override |
|---------|-----------|-----------------------|------------------------|------------------------------|
| `postgres` | Yes | Yes | Yes | Yes |
| `keycloak-postgres` | Yes | Yes | Yes by default | Omitted with external Keycloak |
| `app` | Yes | Yes | Yes | Yes |
| `frontend` | Yes | Yes | Yes | Yes |
| `keycloak` | Yes | Yes | Yes by default | Replaced by external Keycloak auth overlay |
| `docs` | No (optional override) | No (optional override) | No (optional override) | Added by docs overlays |
| `traefik` | Yes | No | No | No |
| `mailpit` | Yes | Yes | No | No |
| `nginx` | No | Yes | No | Yes |
| `action-kraken-segmentation` | Optional | Optional | Optional | Added by `compose.actions.yaml` |
| `action-kraken-layout-training` | Optional | Optional | Optional | Added by `compose.actions.yaml` |

## Public Surface

### Local dev

- `larex.localhost`
- `api.localhost`
- `keycloak.localhost`
- `mail.localhost`
- `docs.localhost` (with `compose.dev.docs.yaml`)

### Local production-like

- `larex.localhost`
- `keycloak.localhost`
- `mail.localhost`
- `docs.localhost` (with `compose.prod.local.docs.yaml`)
- bundled Keycloak is also loopback-bound on `127.0.0.1:8090`

### Opinionated production

- frontend on `127.0.0.1:3000`
- bundled Keycloak on `127.0.0.1:8090`
- docs on `127.0.0.1:3001` (with `compose.prod.docs.yaml`)
- backend internal-only

The backend is intentionally not published in production because browser traffic should go through the frontend BFF layer.

## Core Services

### `postgres`

- Image: `postgres:18.2-alpine`
- Data volume: `postgres_data`
- Network: internal `backend`
- Health check: `pg_isready`

### `keycloak-postgres` (bundled auth only)

- Image: `postgres:18.2-alpine`
- Data volume: `keycloak_postgres_data`
- Network: internal `backend`
- Health check: `pg_isready`

### `app`

- Image: `ghcr.io/ocr4all/larex/backend:${LAREX_IMAGE_TAG:-latest}` by default
- Full image override: `LAREX_BACKEND_IMAGE`
- Network: internal `backend`
- Data volumes: `app_data` and the portable-dump `backup_data` mount
- Health check: `/actuator/health`
- Production default: not published to the host

Annotation edit leases are coordinated by one backend process. Their ordering versions
use a PostgreSQL sequence and remain increasing across lease cleanup and backend
restarts. A version is allocated when lease state changes; ordinary heartbeats retain
the current version. Versions are decimal strings in the HTTP and websocket APIs to
preserve PostgreSQL BIGINT precision. Multiple concurrent backend
replicas require shared lease ownership coordination; the version sequence alone does
not provide that.

### `frontend`

- Image: `ghcr.io/ocr4all/larex/frontend:${LAREX_IMAGE_TAG:-latest}` by default
- Full image override: `LAREX_FRONTEND_IMAGE`
- Network: internal `backend`
- Health check: `/api/health/backend`
- Production default: published on loopback only

### `docs` (docs overlays only)

- Local development builds from `docs/Dockerfile`; production pulls `ghcr.io/ocr4all/larex/docs:${LAREX_IMAGE_TAG:-latest}`
- Full production image override: `LAREX_DOCS_IMAGE`
- Local dev and local production-like routing: `http://docs.localhost`
- Opinionated production publishing: `127.0.0.1:3001` by default

### `keycloak` (bundled auth only)

- Image: `quay.io/keycloak/keycloak:26.7.4`
- Imports `config/keycloak/larex.bootstrap.realm.json`
- Volume: `keycloak_data`
- Health check: `/health/ready` on internal management port `9000`; not the published application port `8090`

### `action-kraken-segmentation` (official Actions fragment only)

- Image: `ghcr.io/ocr4all/larex-action-kraken:${LAREX_ACTION_KRAKEN_IMAGE_TAG:-0.6.0}`
- Profiles: `actions`, `action-kraken`
- Network: internal `backend`
- Host ports: none
- Health check: `/health`
- State volume: `action_kraken_state` for caches and processor data
- Security: read-only root filesystem, dropped capabilities, `no-new-privileges`

### `action-kraken-layout-training` (official Actions fragment only)

- Same Kraken image and profiles as segmentation, with a training entry point
- Internal HTTP port `9000`, no published host ports
- `action_kraken_training_state` holds training caches/data
- `action_kraken_models` is mounted read-write for publishing trained models;
  segmentation mounts that volume read-only for discovery
- Default CPU limit `4`, memory limit `16G`, and temporary storage limit `16g`;
  benchmark your workload before sizing production

See [Official Action Services](/deployment/official-action-services) for configuration and registration.

## Persistent State

| Volume | Contents | Backup priority |
| --- | --- | --- |
| `postgres_data` | LAREX relational data | Required |
| `app_data` | Uploaded and generated project files | Required |
| `backup_data` | Portable Admin Dashboard dumps and reseed markers | Optional; copy or mount externally when using portable dumps |
| `keycloak_postgres_data` | Bundled Keycloak realms, clients, and users | Required with bundled Keycloak |
| `keycloak_data` | Bundled Keycloak runtime/provider state | Preserve with bundled Keycloak |
| `action_kraken_state` | Segmentation caches and processor data | Preserve any operator-installed local data |
| `action_kraken_training_state` | Training caches and processor data | Preserve if needed for your workload |
| `action_kraken_models` | Published trained models shared with segmentation | Required when models cannot be reproduced |

Compose `down` preserves these named volumes. Production backups should capture the
databases, application files, and stable environment/secret configuration together.
Use the unified create, verify, preflight, and restore commands documented in
[Production Deployment](/deployment/production-deploy#persistent-data-and-backups).

## Deployment Shape and Scaling

The supplied topology uses one backend and one frontend. Backend edit-lease
ownership and some application coordination are process-local. Frontend refresh
coordination is also process-local, and active WebSocket connections belong to
the frontend that accepted them. A shared database alone does not make multiple
application replicas safe. Plan shared coordination/session state before scaling
application replicas; see [session refresh](/deployment/keycloak-setup#frontend-session-refresh).

External processor capacity can be scaled separately, subject to the processor's
own queue/model/resource design and Action concurrency limits. Increasing an
Action limit does not add CPU, GPU memory, or processor execution slots.

## Local-Only Services

### `traefik`

Used only for local development to provide stable `*.localhost` hostnames.

### `nginx`

The local production-like overlay uses a basic HTTP-only Nginx proxy for stable `*.localhost` hostnames. It does not mount or access the Docker socket.

### `mailpit`

Used only for local dev and local production-like flows to catch mail without external SMTP.

## Optional Production Nginx

`compose.prod.nginx.yaml` adds:

- `nginx:1.27-alpine`
- port `80` and `443`
- an authentication-specific template selected through `NGINX_TEMPLATE_FILE`

With bundled Keycloak it proxies:

- frontend
- bundled Keycloak

With external Keycloak it proxies only the frontend; the identity provider remains at its existing public URL.

It does not expose the backend directly.
