# Core concepts

A few distinctions make the rest of LAREX easier to navigate. Use this page as a map when an interface label is unfamiliar.

## Where your work lives

| Concept | Meaning | Example |
| --- | --- | --- |
| Workspace | Access boundary containing a library, members, resources, datasets, and assignments. | Your personal workspace or a shared team workspace. |
| Library | Project list for the selected workspace. | Find, filter, star, create, or open projects. |
| Project | Working document container with ordered pages and project settings. | A book or a document batch. |
| Page | A document unit with metadata and one or more image and XML files. | A scanned folio with original and processed image variants. |
| Image variant | A named image representation of a page. | An original scan and a binarized image. |
| Annotation | Layout, text, and metadata represented in XML. The visual editor works with PAGE XML. | Regions, textlines, baselines, reading order, and transcriptions. |
| Toolkit resource | Reusable annotation or review convention assigned to a project. | Label set, codec, dictionary, keyboard, normalization profile, validation ruleset, or tag set. |

Changing the workspace changes the library, search scope, available resources, and management permissions. If a project appears to be missing, check the workspace first.

## Layout, transcription, and variants

**Layout** describes where elements are and how they relate. A text region can contain textlines; a line can have a baseline and transcription alternatives. **Reading order** describes sequence and can matter when a page is flattened into text.

**Transcription** is the text attached to those elements. PAGE XML can store multiple text alternatives, commonly called `TextEquiv` variants, with indices and optional confidence. A project's ground-truth and recognition index settings tell review tools which alternatives to treat as corrected text and recognition results. An image variant and a text variant are different choices.

Saving persists the current annotation. Undo/redo changes the live editing session; version history restores a saved XML checkpoint. Search and most batch operations work on saved/indexed content. See [Text review](/user-guide/text-review) and [History](/user-guide/history-and-collaboration).

## Human work and automated work

| Interface term | Meaning |
| --- | --- |
| Assignment | A unit of coordinated human work, with members, status, priority, due date, and Tasks. |
| Task | A checklist item inside an Assignment; it can be linked to a page and completed while reviewing it. |
| Page state | Open, In progress, or Done for the page. It can be set directly or synchronized from page Tasks. |
| Action | A configured external processor for processing, training, evaluation, or integration. |
| Run | One execution of an Action with selected inputs and parameters. |
| Jobs | Progress and history for background work such as uploads, imports, exports, and Action runs. |

Completing a page Task does not run an Action. An Action finishing successfully does not by itself mean that a person reviewed its result.

## Working collections and frozen deliveries

A **dataset** collects selected page annotations and image variants, potentially from multiple projects, and assigns train/validation/test splits.

- A **live link** uses the project's current source files. Editing through it changes the source annotation.
- A **copy** starts from the selected state and has independent files. Its annotation can still be edited inside the dataset.
- A **release** freezes a downloadable package. Later changes to the working project or dataset do not update that release.

A project can also have releases. A [LAREX project package](/user-guide/projects#export-or-transfer-a-project) is intended for moving editable project content between instances; a dataset package includes curation and split information for reuse. See [Datasets](/user-guide/datasets) and [Exports and sharing](/user-guide/exports-and-sharing).

## Permissions, locks, and quotas

Your global role and your workspace membership serve different purposes. Workspace curators manage projects and resources; editors annotate and review accessible material. A global curator can create team workspaces but does not automatically gain access to every team. Global administrators have instance-wide administration controls.

Even with the right role, an operation can be unavailable because a project/page is locked, another editor holds edit access, an Action has reserved its input scope, or storage quota is exhausted. Start with [Workspaces and permissions](/user-guide/workspace-library), then use [Troubleshooting](/user-guide/troubleshooting) for the specific symptom.
