This tutorial takes one document page from import to a saved annotation and an export. Start with a readable page image. If you already have matching PAGE XML, keep it with the image so you can review existing layout and text.

**You need:** access to a LAREX instance and permission to create a project and upload material in your chosen workspace. Personal workspace owners and team curators can do this. If you are an editor joining a team, ask a curator to prepare the project, then start at [Open the page](#_3-open-the-page).

## 1. Choose a workspace and create a project

1. Sign in and select your personal workspace, or the team workspace where the material belongs.
2. Open the library and choose **New Project**.
3. Give it a recognizable name, such as `First page review`, and create it. You can leave optional toolkit assignments for later.
4. Open the project.

**Check:** the project page table is visible in the intended workspace. A project holds pages; it is not itself a dataset or a processing job.

## 2. Upload one page

1. Choose **Upload Files** and add your image. If you have matching PAGE XML, add it too. Use the same basename, such as `0001.png` and `0001.xml`; the text before the first dot identifies the page.
2. Watch **Jobs** until processing finishes. Resolve any reported filename conflicts before continuing.
3. Inspect the page row and its available image/XML files. If the XML appears on a different page, check the import names and pairing instead of editing the mismatched result.

**Check:** you can see the page image. An image-only page will not already contain regions, textlines, or recognized text. Uploading an image does not run OCR automatically. See [Projects](/user-guide/projects#add-material) for PDF and IIIF imports.

## 3. Open the page

Select your page and choose **Open in Editor**. The editor opens the selected page; with no selection it opens the project's page set.

Use the toolbar's mode-and-view selector to choose **Layout · Hierarchy**. Zoom with the wheel or trackpad and pan on empty canvas space. Open the structure panel to inspect existing regions.

**Check:** the image and overlays describe the same page. If another person currently edits it, request edit access before changing it. See [Collaboration and history](/user-guide/history-and-collaboration).

## 4. Create or correct layout

For existing PAGE XML, select a region in the canvas or structure panel and correct its boundary or label.

For an image-only page:

1. Choose the region rectangle or polygon tool.
2. Draw a text region around a small paragraph. Double-click to finish a polygon.
3. Select the region, switch to **Layout · Text lines**, and draw a textline inside it.
4. Return to the selection tool and inspect the result.

Start with one paragraph and one line. If your workspace offers a layout or recognition Action, you can use it to create a larger starting point after saving; Action availability depends on your administrator and curator.

## 5. Correct text and save

1. Switch to **Text · List** (`5` with default shortcuts).
2. Give the line an editable ground-truth (GT) transcription. Only the variant at the project's GT index is editable; recognition variants are read-only.
   - **New, empty line:** choose **Add** on the line. LAREX adds an empty variant at the lowest free index, which is `0` on an empty line.
   - **Line with recognized text only:** choose **Create GT**. It copies the first non-empty recognition variant into a new GT variant, which you then correct.
   - **Project GT index is not `0`:** a variant created with **Add** may land on index `0` and stay disabled. Select the small index number left of the text field, set it to the project's **Default GT Index**, and save the index. If that index is already used, the two variants swap indices.
3. Enter or correct the GT text while comparing it with the image.
4. Save using the editor's save action or `Ctrl/Cmd+S`.
5. Wait for a successful save. Reopen the page to confirm the layout and text persisted.

Selecting or browsing lines never creates GT by itself. In **Text · Canvas**, typing into a line or choosing **Copy to GT** creates GT for that line only.

**Check:** the saved annotation contains your region, line, and text. Search and exports use saved data; live edits alone are not a durable checkpoint.

The other text views are **Canvas**, for correction directly on the image, and **Full text**, for a continuous transcription beside the canvas. Continue with [Text correction and review](/user-guide/text-review) when working through more than a single line.

## 6. Export the result

Return to the project and open its export menu. Choose a **basic project export** to download current image and XML files, or a **LAREX package** to preserve project structure and assigned resources for re-import.

**Check:** the ZIP contains the expected image and saved XML. Converted text output also depends on having transcription and an appropriate reading order; a blank image alone cannot produce meaningful text.

See [Exports, releases, and sharing](/user-guide/exports-and-sharing) to choose an output for delivery or archiving.
