# Validation Rulesets

Validation rulesets are workspace utilities for checking persisted transcription text against reusable QA rules.

They inspect text and report suspicious patterns without changing the source text.

## What Validation Rulesets Are Used For

Validation rulesets support:

- detecting suspicious transcription patterns
- running regex-based QA checks across project text
- reporting severity, message, and match counts per rule
- previewing rule behavior while editing the ruleset
- validating selected pages or full projects

Validation rulesets complement normalization profiles:

- normalization rewrites text
- validation reports issues in text

## Accessing Validation Rulesets

Open **Validation Rulesets** from the dashboard utilities area.

The ruleset area includes:

- overview/list page
- individual ruleset page
- import/export actions
- workspace/project assignment support

## Validation Ruleset List

The overview page supports:

- search
- standard utility actions
- open/edit/delete access based on permissions

## Creating Validation Rulesets

Validation ruleset metadata includes:

- name
- description
- tags

Each ruleset contains an ordered list of validation rules.

## Rules

Each validation rule can define:

- name
- optional description
- regex pattern
- severity (`INFO`, `WARNING`, `ERROR`)
- optional regex flags
- user-facing message

Typical uses include:

- forbidden characters
- unmatched editorial markers
- repeated punctuation
- malformed notation
- project-specific regex QA

## Ruleset Layout

The validation ruleset detail page uses the standard utility layout:

- metadata sidebar on the left
- main editing area in the center

The main area uses tabs:

- **Rules**
- **Preview**

## Previewing a Ruleset

The preview tab allows you to paste sample text and see what the current rules would flag.

Preview output includes:

- matched rules
- severity
- configured message
- hit counts
- sample matches

The preview uses the current in-page rule state, so you can test unsaved changes before saving the ruleset.

## Defaults and Assignment

Validation rulesets can be assigned as defaults on:

- workspace level
- project level

Workspace defaults are configured in **Workspace Settings**. New projects can inherit the workspace default validation ruleset.

Project-level assignment overrides the inherited workspace default.

## Running Validation on a Project

Project-level validation is available from the project actions menu under **Utilities**.

Current behavior:

- works on selected pages or all pages
- validates project text against the assigned validation ruleset
- opens a results dialog with summary cards and per-rule results
- reports project count, page count, total occurrences, and matched rules
- groups results by matched rule with severity and message

This project validation is independent from dictionary validation and codec validation:

- codecs check character constraints
- dictionaries check token/form membership
- validation rulesets check arbitrary QA patterns
