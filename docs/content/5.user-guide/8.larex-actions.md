# Running LAREX Actions

LAREX Actions run external processors on project data. A curator or editor starts an Action from LAREX, the processor receives selected input files, and LAREX imports the returned PAGE XML or image results.

This page is for users who run Actions. Administrators and processor authors should also read the [LAREX Actions reference](/actions/overview).

## When To Run An Action

Run an Action when a configured processor should help with:

- layout segmentation
- OCR/HTR or text recognition
- PAGE XML enrichment
- image-derived outputs
- workflow automation that returns files to LAREX

Only assigned and enabled Actions appear in project or editor run dialogs. If an expected processor is missing, ask a curator or global administrator to check assignment and availability.

## Start From A Project

1. Open a project.
2. Select pages if the run should be limited.
3. Open **Actions**.
4. Choose **All pages** or **Selected pages**.
5. Select the processor.
6. Choose image variants if the processor accepts images.
7. Start the run.

If the processor is busy and concurrency rules allow queuing, LAREX can schedule the run to start when a slot becomes available.

## Start From The Editor

Use the Action wand or context menu in the editor to run on the active target.

| Target | Typical use |
| --- | --- |
| Page | Re-run OCR/HTR or layout processing for the active page. |
| Region | Re-run layout or recognition for selected regions. |
| Textline | Re-run recognition or cleanup for selected textlines. |

LAREX Actions process saved PAGE XML. If the target page has unsaved changes, LAREX asks you to save before continuing. If saving fails, the Action does not start.

## Choose Image Inputs

When a processor accepts image input, the run dialog can choose which image variant to send.

| Mode | Use it when |
| --- | --- |
| Global variant | Every selected page should use the same image variant. |
| Per-page variant | Pages need different image variants. |
| Fallback enabled | Missing selected variants should fall back to the first available image. |
| Fallback disabled | Pages missing the selected variant should be skipped. |

The processor receives only the pages that remain in scope after image selection.

## Monitor Runs

The run dialog and workspace queue show status, progress, queue position, messages, and history.

Run statuses:

| Status | Meaning |
| --- | --- |
| `QUEUED` | Waiting for a concurrency slot. |
| `PENDING` | Created and waiting for dispatch. |
| `DISPATCHING` | LAREX is sending the dispatch request. |
| `RUNNING` | The processor accepted the run. |
| `IMPORTING_RESULTS` | LAREX is validating and importing returned files. |
| `COMPLETED` | Results were imported successfully. |
| `FAILED` | Dispatch, processing, validation, or import failed. |
| `CANCEL_REQUESTED` | Cancellation was requested and the processor should stop cooperatively. |
| `CANCELLED` | The run ended as cancelled. |

Active runs can lock affected pages or the whole project depending on the Action definition.

## Cancel Or Retry

Queued or pending runs can be cancelled before processing starts. Running processors are cancelled cooperatively: LAREX records the request, and the processor must observe heartbeat cancellation and stop.

Failed or cancelled runs can be retried. Retry creates a new run with the same Action, target scope, and resolved parameters.

## Understand Result Import

Actions may return PAGE XML, images, or both.

- Page-targeted XML replaces or appends according to the Action output mode.
- Region-targeted XML imports only the selected regions from returned PAGE XML.
- Textline-targeted XML imports only the selected textlines from returned PAGE XML.
- Image results are stored under the result variant declared by the processor result or Action definition.

After import, LAREX refreshes affected page data and search/index state.
