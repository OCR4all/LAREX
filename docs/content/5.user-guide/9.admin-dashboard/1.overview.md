# Admin Dashboard

The Admin Dashboard is available to users with the `GLOBAL_ADMIN` role. It provides instance-wide views and maintenance workflows that go beyond a single workspace: user lifecycle management, global role review, workspace access, storage quotas, server-side import, backup/reseed jobs, search index rebuilds, error inspection, application health, and LAREX Action administration.

Open it from **Admin** in the navigation or command palette. The dashboard overview groups pages by system, data management, directory, and Actions workflows.

## Capabilities

| Admin page | Use it for |
| --- | --- |
| [Users and Global Roles](/user-guide/admin-dashboard/users-and-global-roles) | Create local users, resend setup emails, enable or disable accounts, inspect user details, audit administrative changes, and manage `GLOBAL_CURATOR`. |
| [Quotas and Storage](/user-guide/admin-dashboard/quotas-and-storage) | Increase workspace quota, reset quotas to defaults, recalculate usage, review exceeded workspaces, and delete orphaned files. |
| [Workspaces, Import, and Backup](/user-guide/admin-dashboard/workspaces-import-backup) | Browse every workspace, open a workspace in admin mode, import server-side datasets, and run dump or reseed jobs. |
| [Monitoring and Actions](/user-guide/admin-dashboard/monitoring-and-actions) | Rebuild search indexes, inspect API error events, check application health, monitor Action runs, cancel runs, and reach Action definition administration. |
| Avatar Settings | Choose the instance-wide generated avatar style used for users, projects, and workspaces without a custom image. |
| IIIF Settings | Review the deployment download interval, apply or reset the instance-wide runtime override, and confirm the effective per-host pacing value. |

## Access Boundaries

Admin pages are global, but they do not bypass every system boundary.

- LDAP-managed users must be changed in the external directory or identity provider.
- Service accounts are listed separately from normal users and cannot be managed from the user lifecycle controls.
- Workspace quota changes affect uploads, imports, and Action result imports for that workspace.
- Storage cleanup deletes files that LAREX considers orphaned, so review filters and selections before bulk deletion.
- Backup, reseed, and server-side import operate on server paths that must be reachable by the backend container or host process.

| Need | Start here |
| --- | --- |
| A workspace cannot upload or import because quota is exceeded. | [Increase or recalculate quota](/user-guide/admin-dashboard/quotas-and-storage#increase-a-workspace-quota). |
| A new local user needs access. | [Create a user](/user-guide/admin-dashboard/users-and-global-roles#create-a-local-user). |
| A curator should be able to create team workspaces. | [Grant `GLOBAL_CURATOR`](/user-guide/admin-dashboard/users-and-global-roles#manage-global-curator). |
| A server directory should be imported into a project. | [Run server-side import](/user-guide/admin-dashboard/workspaces-import-backup#server-side-import). |

| A processor run is stuck or queued. | [Inspect Action runs](/user-guide/admin-dashboard/monitoring-and-actions#action-runs). |

| IIIF imports are too slow or a provider requires gentler pacing. | Open **Admin → IIIF Settings** and adjust the minimum download interval. |

## Avatar Settings

LAREX generates deterministic avatars when no custom user image exists. Gradient is the initial
instance default. A global administrator can switch the generated style to Identicon, Flow Field,
or Initials from **Admin → Avatar Settings**. The selected style applies after reload for other
active sessions; custom profile images always take precedence.

Users upload or remove their profile image from **Settings → Profile**. LAREX validates JPEG, PNG,
and WebP files up to 5 MB, crops them to a square, and stores the processed image in backend-managed
persistent storage. Avatar images are not stored in Keycloak or an external identity directory.

## IIIF Request Pacing

IIIF previews and image downloads use separate queues. Preview metadata is not delayed by normal download pacing and preview generation does not probe each remote image for its size. Both queues still honor a shared cooldown for a host after HTTP 429, or HTTP 503 with `Retry-After`.

The IIIF Settings page shows:

- the deployment default, normally 100 ms
- an optional database-backed admin override
- the effective minimum interval between download starts to the same host

Use `0` only when the remote providers can tolerate unrestricted download starts. Adaptive server-directed cooldown remains enabled at every value. Reset the override to follow the deployment environment again.
