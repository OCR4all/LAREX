# Admin Dashboard

The Admin Dashboard is available to users with the `GLOBAL_ADMIN` role. It provides instance-wide views and maintenance workflows that go beyond a single workspace: user lifecycle management, global role review, workspace access, storage quotas, server-side import, backup/reseed jobs, search index rebuilds, error inspection, application health, and LAREX Action administration.

Open it from **Admin** in the navigation or command palette. The dashboard overview groups pages by system, data management, directory, and Actions workflows.

## Capabilities

| Admin page | Use it for |
| --- | --- |
| [Users and Global Roles](/user-guide/admin-dashboard/users-and-global-roles) | Create local users, resend setup emails, enable or disable accounts, inspect user details, audit administrative changes, and manage `GLOBAL_CURATOR`. |
| [Quotas and Storage](/user-guide/admin-dashboard/quotas-and-storage) | Increase workspace quota, reset quotas to defaults, recalculate usage, review exceeded workspaces, and delete orphaned files. |
| [Workspaces, Import, and Backup](/user-guide/admin-dashboard/workspaces-import-backup) | Browse every workspace, open a workspace in admin mode, import server-side datasets, and run dump or reseed jobs. |
| [Monitoring and Actions](/user-guide/admin-dashboard/monitoring-and-actions) | Rebuild search indexes, inspect API error events, check application health, monitor Action runs, cancel runs, and reach Action definition administration. |

## Access Boundaries

Admin pages are global, but they do not bypass every system boundary.

- LDAP-managed users must be changed in the external directory or identity provider.
- Service accounts are listed separately from normal users and cannot be managed from the user lifecycle controls.
- Workspace quota changes affect uploads, imports, and Action result imports for that workspace.
- Storage cleanup deletes files that LAREX considers orphaned, so review filters and selections before bulk deletion.
- Backup, reseed, and server-side import operate on server paths that must be reachable by the backend container or host process.

| A curator should be able to create team workspaces. | [Grant `GLOBAL_CURATOR`](/user-guide/admin-dashboard/users-and-global-roles#manage-global-curator). |

| Page search or label filters are stale. | [Rebuild the search index](/user-guide/admin-dashboard/monitoring-and-actions#search-index). |
| A processor run is stuck or queued. | [Inspect Action runs](/user-guide/admin-dashboard/monitoring-and-actions#action-runs). |
