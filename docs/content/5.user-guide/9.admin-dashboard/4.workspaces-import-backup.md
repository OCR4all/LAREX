# Workspaces, Import, and Backup

Global administrators can inspect all workspaces, enter a workspace in admin mode, import files from server paths, and run file-data dump or reseed jobs.

## Workspace Management

Open **Admin -> Workspaces** to view every personal and team workspace. The table shows:

- workspace name and secondary label
- workspace type: personal or team
- owner
- member count
- project count
- creation date

Use search to find a workspace by name, owner, or ID.

## Open A Workspace As Admin

Select **Open** on a workspace row. LAREX switches the active workspace context and shows a warning toast that you are viewing the workspace as administrator.

Use admin mode when you need to inspect workspace state, troubleshoot a user report, or verify project data. Leave workspace-level changes to normal curator flows unless administrative intervention is required.

## Server-Side Import

Open **Admin -> Import** to import files that already exist on the server or backend container filesystem.

1. Enter the absolute server path.
2. Wait for path validation.
3. Select the target workspace.
4. Select the target project.
5. Enable **Overwrite existing files** only when intentional.
6. Select **Scan Directory**.
7. Review image count, XML count, total size, conflicts, warnings, and quota status.
8. Select **Start Import**.

The import job runs in the background. The job list shows status, progress, processed/skipped/failed file counts, error messages, completion time, and cancellation for pending or active jobs.

## Import Conflicts And Quota

The scan phase identifies conflicts before the import starts. If the scan reports quota exceeded, LAREX blocks the import. Increase workspace quota or free storage, then scan again.

Use overwrite carefully. It allows imported files to replace existing project files when conflicts are detected.

## Backup And Reseed

Open **Admin -> Backup** to create, verify, or reseed portable application-data
dumps.

| Job type | Use it for |
| --- | --- |
| Create portable dump | Export workspace toolkits and project packages, including PAGE XML history. |
| Verify portable dump | Validate its structure and every SHA-256 checksum without importing data. |
| Reseed from dump archive | Import portable data into existing or mapped workspaces. |

Verify and reseed validate their source archive path before starting. Jobs run in
the background and can be monitored from the job list. Dumps and reseed
completion markers are always written to the operator-configured backup
directory; administrators cannot change that server path from the browser.

These jobs serve a different purpose from **Admin -> Import**, which ingests an
existing image/PAGE XML directory into one project. They also differ from an
operator's full-instance snapshot, which captures PostgreSQL, `app_data`, and
optional bundled Keycloak state. Do not pass a full-instance `.tar.gz` snapshot
to Import or Reseed. See
[Production Deployment](/deployment/production-deploy#persistent-data-and-backups)
for full backup and disaster recovery.

## Start A Dump Job

1. Open **Admin -> Backup**.
2. Choose **Create portable dump**.
3. Under **Dump Scope**, choose **All workspaces** or select one workspace.
4. Start the job.
5. Select the job to inspect progress, result path, warnings, or errors.

New dumps use manifest schema 1.0 and contain SHA-256 checksums for each toolkit
and project package. A single-workspace dump uses the same format as a complete
portable dump, so it can be verified and reseeded in the same way.

## Verify A Dump

1. Open **Admin -> Backup**.
2. Choose **Verify portable dump**.
3. Enter the source dump path.
4. Start the job.
5. Confirm the job completes before copying or reseeding from the archive.

## Start A Reseed Job

1. Open **Admin -> Backup**.
2. Choose **Reseed from dump archive**.
3. Enter the source dump path.
4. Optionally enter workspace ID mappings as `source=target` pairs separated by commas.
5. Start the job.

Workspace mapping is useful when restoring data into workspaces with different IDs than the source dump.

Administrative dumps always include PAGE XML version history in their embedded project packages.
Reseed verifies a schema 1.0 dump's checksums before writing toolkit or project data.

## Cancel Jobs

Pending or running import and backup jobs expose a cancel action. Cancellation stops future processing where supported, but already processed files may remain and should be reviewed after the job settles.
