# Normalization

Normalization profiles are workspace toolkit resources that standardize transcription text according to reusable rules.

They are used before or alongside search, QA, and export workflows.

## What Normalization Is Used For

Normalization profiles support:

- standardizing historical characters and punctuation
- applying reusable cleanup rules such as whitespace cleanup
- applying reusable manual replacement rules
- previewing how persisted project text would change
- applying normalization to project text variants

Normalization changes text. It is different from validation rulesets, which only report suspicious patterns.

## Accessing Normalization Profiles

Open **Normalization Profiles** from the dashboard toolkit area.

The normalization area includes:

- overview/list page
- individual normalization profile page
- import/export actions
- workspace/project assignment support

## Normalization Profile List

The overview page supports:

- search
- standard toolkit actions
- open/edit/delete access based on permissions

## Creating Normalization Profiles

Normalization profile metadata includes:

- name
- description
- tags
- Unicode normalization mode

New profiles do not enable any preset rules by default.

## Profile Layout

The normalization detail page uses the same toolkit layout as other workspace toolkit resources:

- metadata sidebar on the left
- main configuration area in the center

The metadata sidebar contains the profile identity fields and Unicode normalization.

The main area uses tabs:

- **Rules**
- **Preview**

## Built-In Preset Rules

Preset rules are optional cleanup toggles such as:

- ligature expansion
- long-s normalization
- quotation mark normalization
- dash normalization
- whitespace collapsing
- trimming
- dehyphenation across line breaks

Each built-in preset rule has a hover help popover that explains what it does in more detail.

## Manual Replacement Rules

Normalization profiles can also include ordered manual replacement rules.

Each replacement rule stores:

- search pattern
- replacement text
- mode: plain text or regex

Rules are applied in order. Regex rules are validated when the profile is saved.

## Previewing a Profile

The profile page includes a local preview tab with:

- input sample
- normalized output

This is useful for testing preset rules and manual replacement rules before assigning the profile to projects.

## Defaults and Assignment

Normalization profiles can be assigned as defaults on:

- workspace level
- project level

Workspace defaults are configured in **Workspace Settings**. New projects can inherit the workspace default normalization profile.

Project-level assignment overrides the inherited workspace default.

## Running Normalization on a Project

Project normalization is available from the project actions menu under **Toolkit**.

Current behavior:

- works on selected pages or all pages
- opens in a slideover
- shows the assigned normalization profile
- lets you inspect the active preset rules and manual replacement rules
- previews affected rows before any write is performed
- highlights original and normalized differences row by row
- shows which normalization rules matched each changed row when available

Normalization runs against a specific text variant index:

- default target: the project GT index
- optional override: a custom non-negative index

From the project normalization slideover you can:

- refresh the result set
- apply normalization for a single row
- apply normalization for the full preview scope
- cancel without writing anything

## Notes on Performance

Preview generation is optimized on the backend by compiling the normalization plan once per request and analyzing preview rows in parallel.

Applying normalization still writes through the regular PAGE XML save/index pipeline, so it can take longer than preview generation on larger projects.
