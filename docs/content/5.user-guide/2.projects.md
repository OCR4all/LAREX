# Projects

A project is the working container for a document or collection segment. It holds pages, images, PAGE XML files, tags, task state, resource assignments, and processing history.

## Create A Project

From the library, choose **New Project** and enter the required project name. Curators can also add:

- description
- project tags
- tag set
- codec
- dictionary
- label set
- normalization profile
- validation ruleset
- default ground-truth index
- default recognition indices

The assigned resources shape editor behavior, validation, search, and review workflows. They can be changed later from project settings.

## Add Material

Projects can receive material through uploads or IIIF import.

### Upload Files

Use **Upload Files** for local files.

Accepted inputs:

- images
- PAGE XML files
- PDFs

For PDFs, LAREX asks for a page prefix before processing. Upload progress is tracked, and unresolved conflicts appear as a project warning.

Conflict choices:

| Choice | Result |
| --- | --- |
| Keep existing | Ignore the incoming conflicting file. |
| Replace existing | Replace the current project file. |
| Rename upload | Keep both by storing the new file under a different name. |

### Import IIIF

Use **Import IIIF** for public IIIF Presentation manifests or collections.

Supported sources:

- manifest URL
- uploaded manifest JSON file
- IIIF Presentation API v2
- IIIF Presentation API v3
- IIIF collections with manifest expansion

The preview step shows metadata, canvases, thumbnails, warnings, and estimated storage. To keep previews responsive and avoid contacting every image endpoint, LAREX approximates image sizes from manifest dimensions and image formats with a safety margin. Images without usable dimensions use a 10 MB fallback during quota preflight. You can import all importable canvases, manually choose canvases, or select a start/end range.

Each imported canvas becomes one LAREX page with a local `iiif` image variant. IIIF import does not create PAGE XML automatically.

IIIF download jobs from different projects share a durable instance-wide queue. They appear in the global **Jobs** panel with their queue position, progress, cancel action, and completed history, including after a page reload. Pending jobs are recovered after a backend restart. To prevent stale previews from creating duplicate pages, only one active or queued IIIF import is allowed per project.

If an imported canvas collides with an existing page, choose:

| Choice | Result |
| --- | --- |
| Skip | Keep the existing page and do not import that canvas. |
| Rename | Create a new page with a different name. |
| Replace IIIF Image | Reuse the existing page and replace its `iiif` image variant. |

After a partial failure, **Retry Failed** creates a new import job for failed canvases only.

## Work With Pages

The page table is the project control surface. It shows page name, description, tags, image count, XML state, index state, task state, update time, and row actions.

Common page tasks:

- edit page metadata
- inspect images
- view or edit raw PAGE XML
- export XML
- open version history
- delete pages
- select pages for batch actions
- open selected pages in the editor
- run LAREX Actions on selected pages

## Edit PAGE XML Directly

Use **View/Edit XML** when you need raw PAGE XML access.

The XML editor:

- loads the first PAGE XML file for the page
- validates against bundled PAGE schemas
- blocks saving invalid XML
- supports find and replace with `Ctrl/Cmd+F` and `Ctrl/Cmd+H`
- keeps version history separate from the editing surface

Supported PAGE schema versions include `2010-03-19`, `2013-07-15`, `2016-07-15`, `2017-07-15`, `2018-07-15`, `2019-07-15`, and `2024-07-15`.

## Open Pages In The Editor

Use **Open in Editor** from the project header.

- If pages are selected, LAREX opens the selected pages.
- If no pages are selected, LAREX opens the project page set.
- Hovering or focusing the editor action starts prefetching for faster navigation.

Workspace search results can also open a page directly in text mode with the search term already applied.

## Run Project-Level Actions

The project Action dialog can run assigned processors on:

- all pages
- selected pages

If the processor accepts images, choose the image variant globally or per page. Missing selected variants can either fall back to the first available image or skip affected pages.

See [Running LAREX Actions](/user-guide/larex-actions).
