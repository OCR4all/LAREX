# Projects

This page describes the current project view (`/project/:id`) behavior.

## Project Page Overview

The project page combines project-level actions and a page table.

### Header Actions

- Star/unstar project
- Open in Editor
- Upload Files
- Import IIIF
- Actions menu (project-level actions)
- Storage usage indicator (when available)

## Uploading Files

### Accepted Types

- Images (`image/*`)
- XML (`.xml`)
- PDF (`application/pdf`, `.pdf`)

### Upload Flow

1. Click **Upload Files**.
2. Select one or more files.
3. For PDFs, set a page prefix in the PDF prefix slideover.
4. Upload starts and progress is tracked.

When a project has unresolved upload conflicts, a warning banner appears with **Resolve Conflicts**.

### Conflict Resolution Options

- Keep existing file
- Replace existing file
- Rename uploaded file and keep both

## Importing IIIF Manifests

Use **Import IIIF** from the project header to create pages from a public IIIF Presentation manifest.

### Supported Sources

- Manifest URL
- Uploaded manifest JSON file

### Supported IIIF Versions

- IIIF Presentation API v2
- IIIF Presentation API v3

### Import Flow

1. Click **Import IIIF**.
2. Choose **Manifest URL** or **Manifest File**.
3. Preview the manifest before import.
4. Review manifest metadata, canvas count, estimated storage, and warnings.
5. Resolve any page conflicts.
6. Start the import and wait for the job to finish.

### What Import Creates

- Each importable canvas becomes one LAREX page.
- The imported page gets one local `iiif` image variant.
- No PAGE XML is created automatically.
- IIIF provenance is stored on the page for traceability.

### Naming Rules

- First choice: normalized canvas label
- Fallback: manifest label with a zero-padded canvas index
- Final fallback: `canvas-0001`, `canvas-0002`, ...

### IIIF Conflict Resolution Options

When an imported canvas would collide with an existing page, you can choose:

- **Skip**: keep the existing page and do not import that canvas
- **Rename**: create a new page with a different page name
- **Replace IIIF Image**: reuse the existing page and replace its `iiif` image variant

### Preview Warnings And Errors

The preview step reports issues before import starts, for example:

- canvases without a usable image
- manifests that are not publicly reachable
- HTTP access problems such as `401`, `403`, or `404`
- storage estimation warnings

The import result also reports per-canvas failures, so partial imports are visible instead of failing silently.

### Current Limitations

- Public, unauthenticated manifests only
- No IIIF collections
- No IIIF text, OCR, or annotation import
- One imported image per canvas in the current version

## Managing Pages

### Page List Columns

| Column | Description |
|--------|-------------|
| **Select** | Row checkbox |
| **Name** | Page name |
| **Description** | Optional page description |
| **Tags** | Assigned tags |
| **Images** | Number of images on the page |
| **XML** | XML presence (`Yes`/`No`) |
| **Indexed** | Indexing state (`Yes`, `No`, `Indexing`, `Empty`) |
| **My Tasks** | Open subtasks badge (if any) |
| **Updated** | Last update timestamp |
| **Actions** | Dropdown menu |

### Page Actions

| Action | Description |
|--------|-------------|
| **Edit** | Update page name, description, and tags |
| **View Images** | Open image viewer slideover |
| **View/Edit XML** | Open raw PAGE XML editor for the first PAGE XML on that page |
| **Export XML** | Export page XML (first XML variant) |
| **Version History** | Open XML version history |
| **Delete** | Remove page and related files |

### View/Edit XML

The **View/Edit XML** action opens a raw PAGE XML slideover editor for the first PAGE XML file on the selected page.

Current behavior:

- XML is loaded as raw text with validation diagnostics.
- Validation runs against bundled PAGE XSD schemas.
- Save is enabled only when the document has changes and the XML is valid.
- Invalid XML cannot be saved.
- Version history remains available separately via **Version History**.

Supported PAGE schema versions for validation:

- `2010-03-19`
- `2013-07-15`
- `2016-07-15`
- `2017-07-15`
- `2018-07-15`
- `2019-07-15`
- `2024-07-15`

Search and replace in the XML editor:

- Use **Find / Replace** to toggle the search panel.
- Keyboard shortcuts: `Ctrl/Cmd+F` and `Ctrl/Cmd+H`.
- The panel can be closed by clicking **Find / Replace** again or clicking outside the search/editor area.

### Bulk Actions

- Multi-select pages with row checkboxes.
- Use the trash action to bulk delete selected pages.
- Selection also scopes project-level actions like codec generation/validation and package export.

## Opening in Editor

`Open in Editor` loads:
- Selected pages, when at least one page is selected
- All pages, when nothing is selected

On hover/focus, prefetching starts for:
- Selected pages, or
- First 5 pages when no selection exists

Workspace text search can also open a page directly in text mode with the search term pre-applied as an editor text filter.

## Project Settings

### Editing Project Settings

Use **Actions → Edit project**.

### Available Settings

| Setting | Description |
|---------|-------------|
| **Name** | Project name |
| **Description** | Project description |
| **Tags** | Project-level tags |
| **Tag Set** | Optional tag set reference |
| **Primary Codec** | Codec used by codec actions |
| **Default Dictionary** | Dictionary used for token validation and suggestions |
| **Normalization Profile** | Profile used for project normalization workflows |
| **Validation Ruleset** | Ruleset used for project-level text QA |
| **Label Set** | Label set used by editor/project |
| **Default GT Index** | Default GT index for text editor workflows |
| **Default Recognition Indices** | Default recognition indices |

Only workspace owners can edit default text-index settings.

## Project Actions Menu

From the header actions dropdown:

- Actions are grouped into **Project**, **Export**, and **Utilities** sections.

- Generate codec (selected pages or all pages)
- Validate codec (selected pages or all pages)
- Validate dictionary (project text against assigned dictionary)
- Normalization (selected pages or all pages)
- Validate ruleset (selected pages or all pages)
- Export output (selected pages or full project)
- Export package (selected pages or full project)
- Edit project
- Share project
- Delete project

IIIF import is a direct header action, not part of the project actions dropdown.

### Normalization

The **Normalization** action runs against the assigned normalization profile.

Current behavior:

- opens in a slideover instead of a modal
- previews changed rows before applying writes
- shows the assigned normalization profile and its rules
- highlights original vs normalized text changes
- can apply a single changed row or the full preview scope
- runs against the project GT index by default, with optional manual index override

### Validation Ruleset

The **Validate ruleset** action runs the assigned validation ruleset against selected pages or the full project.

Results include:

- analyzed project/page counts
- total occurrence count
- matched rules
- severity and rule message

## Pagination

- Per-page options: `10`, `25`, `50`, `100`
- Standard page navigation controls

### Sorting

- Available sort toggles in table headers include:
  - Name
  - Images
  - Updated

### Filtering

- Search by page text (`Search pages...`)
- Filter by tags (multi-select with OR/AND operator)
- Filter by XML status (`All`, `With XML`, `Without XML`)
- Active filters are shown as removable badges
- **Clear Filters** resets all filters
