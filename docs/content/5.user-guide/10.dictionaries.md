# Dictionaries

Dictionaries are controlled form lists used to validate persisted and in-editor transcription text.

They are implemented as workspace utilities, similar to codecs, label sets, tag sets, virtual keyboards, normalization profiles, and validation rulesets.

## What Dictionaries Are Used For

Dictionaries support:

- validating transcription text against an allowed form list
- highlighting unknown tokens in editor text view
- suggesting close matches for suspicious tokens
- maintaining workspace- or project-level controlled vocabularies

Version 1 is exact-form based. It does not automatically expand lemmas, morphology, or inflection rules.

## Accessing Dictionaries

Open **Dictionaries** from the dashboard utilities area.

The dictionary area includes:

- overview/list page
- individual dictionary page
- import/export actions
- workspace/project assignment support

## Dictionary List

The overview page supports:

- search
- standard utility actions
- open/edit/delete access based on permissions

## Creating Dictionaries

You can create a dictionary in two ways:

1. Create an empty dictionary and add entries manually.
2. Create a dictionary directly from an uploaded file.

Dictionary metadata includes:

- name
- description
- tags
- case sensitivity
- Unicode normalization
- lock state

## Entries

Each dictionary entry stores one accepted surface form.

On the dictionary detail page you can:

- browse entries
- search entries
- add entries manually
- edit entries
- delete entries
- import additional entries

Large dictionaries use virtualized browsing rather than rendering the full list at once.

## Supported Import Formats

Current import support includes:

- `TXT`
- `CSV`
- `TSV`
- `JSON`
- `TEI`

### TXT

- plain text is treated as a corpus
- each whitespace-separated token is imported as an accepted form

### CSV / TSV

- use a `form` column when available
- single-column files are also supported
- extra columns are preserved as entry metadata

### JSON

Supported JSON shapes include:

- native LAREX dictionary payloads
- arrays of strings
- arrays of entry-like objects
- plain word maps such as `{ "word": 1 }`

`*.larex-utilities.json` files are not imported through the dictionary form importer. Use the utility package import flow for those.

### TEI

TEI dictionary-style XML import extracts accepted forms from dictionary entries and orthographic forms.

## Import and Export Behavior

### Create From Import

On a new dictionary page, uploading a file creates the dictionary from that file and then opens it.

### Import Into Existing Dictionary

On an existing dictionary page, uploading adds entries to that dictionary.

### Export

Dictionaries can be exported through the dictionary actions menu and through utility/package flows where applicable.

## Defaults and Assignment

Dictionaries can be assigned as defaults on:

- workspace level
- project level

Project-level assignment overrides the inherited workspace default.

These defaults determine which dictionary the editor and validation actions use.

## Permissions

Dictionary management is restricted.

Owners and curators can:

- create and edit dictionaries
- delete dictionaries
- set workspace/project default dictionaries
- add or edit dictionary entries

Editors can use assigned dictionaries in review workflows but cannot manage dictionary assignments or modify dictionary contents.

## Locked Dictionaries

Dictionaries have a `locked` option.

When a dictionary is locked:

- editor-side quick-add actions are hidden
- words cannot be added from the editor workflow

This lock applies even if the current user would otherwise have dictionary-edit rights.

## Dictionary Use in the Editor

When a project has a dictionary assigned, text view can use it for dictionary checks.

Available behaviors include:

- underline or mark tokens that are not present in the assigned dictionary
- show closest-match suggestions for a selected or hovered token
- open the assigned dictionary in a browsing slideover
- replace a token with a suggested dictionary entry

If the dictionary is editable and not locked, curators/owners can add a token directly from the editor.

## Dictionary Validation

Dictionary validation is available for project text against the assigned dictionary.

Validation results include:

- unknown tokens
- counts and summary information
- page references
- suggestions for suspicious tokens

This is separate from codec validation:

- codecs validate character-level constraints
- dictionaries validate token/form-level constraints

## Suggestions

When a token is not found, the dictionary workflow can suggest close matches.

Suggestions are based on normalized token comparison and edit-distance style lookup, not on linguistic analysis.

## Notes on Performance

Large dictionaries are not shipped wholesale into the editor for client-side checking.

Dictionary token checks and suggestion lookups are resolved through backend-backed lookup flows so projects remain usable with large dictionaries.
