# Tag Sets

Tag sets define the controlled vocabulary used to classify projects and pages. They make filtering, handoff, and review easier because teams use the same labels for the same concepts.

## When To Use Tags

Use tags for information that helps organize or filter material:

- project phase
- source collection
- quality state
- review priority
- page type
- language or script notes
- workflow grouping

Do not use tags for text that belongs in PAGE XML, project descriptions, or detailed metadata fields.

## Create A Tag Set

1. Open the tag set area from the toolkit navigation.
2. Create a new tag set.
3. Add tags with clear names.
4. Group related tags when the hierarchy helps users choose correctly.
5. Assign the tag set to a workspace or project.

Prefer short, recognizable tag names. Long process descriptions are harder to scan in tables and filters.

## Assign Tags

Tags can be assigned to projects and pages where the current resource configuration allows it. Project tags are useful in the library. Page tags are useful in the project table, editor navigation, and filtered review.

## Filter With Tags

The library and project pages support tag filtering. Use:

- **Match any** when a result can have one of several tags.
- **Match all** when a result must have every selected tag.

For review queues, start broad with **Match any**, then narrow with **Match all** after you understand the data.

## Maintain Tag Sets

Review tag sets periodically. Remove unused tags only when you understand how existing projects use them, and rename tags carefully because names are part of the user-facing workflow.
