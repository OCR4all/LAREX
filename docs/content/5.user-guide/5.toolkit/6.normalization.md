# Normalization

Normalization profiles describe how text should be transformed for comparison, review, or downstream processing. They help projects handle consistent variation without changing the underlying transcription every time.

## When To Use Normalization

Use normalization when reviewers need a consistent view over text variants such as:

- case differences
- diacritics
- historical spelling variants
- punctuation conventions
- whitespace or separator differences
- project-specific replacement rules

Normalization should support review. It should not hide uncertainty in the source transcription.

## Create A Profile

1. Open **Normalization** from the toolkit.
2. Create a profile with a descriptive name.
3. Add rules in the order they should apply.
4. Test rules against representative text.
5. Assign the profile to a workspace or project.

Document why each non-obvious rule exists. Future curators need to know whether a rule reflects a source convention, an OCR cleanup habit, or an export requirement.

## Use In Review

Normalization works best together with dictionaries, validation rulesets, and search. For example:

- normalize before comparing tokens to a dictionary
- search for normalized variants during quality checks
- validate text against project conventions

If a normalized result looks wrong, check the rule order before changing source text.
