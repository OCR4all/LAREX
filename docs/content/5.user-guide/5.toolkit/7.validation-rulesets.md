# Validation Rulesets

Validation rulesets collect checks that help teams find quality issues. They are useful when a project has rules that cannot be captured by labels, dictionaries, or manual review alone.

## What To Validate

Good validation rules focus on actionable problems:

- missing required structures
- inconsistent labels
- unexpected text patterns
- metadata omissions
- project-specific annotation conventions
- page states that need curator review

Avoid rules that produce warnings users cannot act on. Too many low-value findings make reviewers ignore the validation surface.

## Create A Ruleset

1. Open **Validation Rulesets** from the toolkit.
2. Create a ruleset for a specific project type or workflow.
3. Add checks with clear names.
4. Test on known good and known problematic pages.
5. Assign the ruleset as a workspace preset or project setting.

Use the ruleset description to explain when it should be used.

## Review Results

Treat validation as a queue of things to inspect, not as an automatic replacement for human judgment. Some findings may be acceptable for a specific source page.

After fixing PAGE XML or text, save the page and allow indexing or validation state to refresh before checking again.
