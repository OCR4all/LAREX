# Private Access Tokens (PAT)

Private Access Tokens (PAT) allow scripted access to a restricted public API surface for automation workflows (for example HPC/Slurm jobs).

PAT access is intentionally limited to data operations and is always workspace-scoped.

## Enablement Flow

PAT usage has two gates:

1. A `GLOBAL_ADMIN` must enable PAT access for a user in **Admin → User Management → User Details → Global Permissions → PAT Access**.
2. The user creates and manages PATs in **Settings → Security → Private Access Tokens (PAT)**.

Token lifecycle remains UI/session-only:

- create token
- list token metadata
- revoke token

No PAT lifecycle endpoints are exposed on the PAT public API.

## Security Model

- PAT secrets are shown once at creation time.
- Backend stores hash only (not plaintext token).
- PATs are workspace-scoped.
- PATs are scope-scoped (`xml:read`, `xml:write`).
- PATs cannot access admin/global-admin actions.
- PAT access can be revoked centrally by global admin (per-user PAT enable/disable).
- Revoked or expired PATs are rejected.

## PAT API Endpoints

All endpoints below are under `/api/public/pat/*` on the frontend proxy.

### Discovery Endpoints

- `GET /api/public/pat/projects`
  - Lists projects available in the PAT workspace.
  - Optional query `workspaceId` is accepted but must match PAT workspace.
- `GET /api/public/pat/workspaces/{workspaceId}/projects`
  - Lists projects for that workspace (must equal PAT workspace).
- `GET /api/public/pat/projects/{projectId}`
  - Returns project details including pages and available image/xml variants.

### XML Data Endpoints

- `GET /api/public/pat/projects/{projectId}/pages/{pageId}/xml/{xmlId}/text` (`xml:read`)
- `PUT /api/public/pat/projects/{projectId}/pages/{pageId}/xml/{xmlId}/text` (`xml:write`)
- `POST /api/public/pat/projects/{projectId}/pages/{pageId}/xml` (multipart upload, `xml:write`)
- `GET /api/public/pat/projects/{projectId}/pages/xml/{xmlId}/export` (`xml:read`)
- `GET /api/public/pat/projects/{projectId}/pages/images/{imageId}/export` (`xml:read`)

## Python CLI Example

A small demo CLI is included at:

- `scripts/pat_cli.py`

Install dependency:

```bash
pip install click
```

Set environment:

```bash
export LAREX_BASE_URL="https://your-larex.example.org"
export LAREX_PAT="lrx_pat_..."
```

Explore:

```bash
python scripts/pat_cli.py projects
python scripts/pat_cli.py project <project-id>
```

Download project files:

```bash
python scripts/pat_cli.py download-xml <project-id> <xml-id> --output ./downloads/file.xml
python scripts/pat_cli.py download-image <project-id> <image-id> --output ./downloads/file.png
python scripts/pat_cli.py download-project <project-id> --out-dir ./downloads --image-variant raw --xml-variant ocr
python scripts/pat_cli.py download-project-xmls <project-id> --out-dir ./downloads --xml-variant ocr
```

## Typical HPC Workflow

1. Discover projects and variants with `projects` / `project` commands.
2. Download selected XML and image files to cluster storage.
3. Run inference/training pipeline on cluster.
4. Push processed XML back using `PUT .../xml/{xmlId}/text` or upload endpoint.
5. Revoke PAT when no longer needed.

## Troubleshooting

- `401 Unauthorized`: invalid/missing/expired/revoked PAT.
- `403 Forbidden`: missing required scope (for example using read-only token for write).
- `404 Not Found`: resource does not exist or is outside PAT workspace.
