# YAML Reference

Action definitions are strict YAML documents. Unknown fields are rejected. The only supported definition version is `1`.

## Complete Example

```yaml
version: 1
id: ocr-inference
name: OCR Inference
description: Run OCR on selected page images.
category: OCR_HTR
targets:
  - PAGE
  - REGION
  - TEXT_LINE

endpoint:
  url: https://ocr.example.org/dispatch
  healthUrl: https://ocr.example.org/health
  preflightUrl: https://ocr.example.org/preflight
  timeoutSeconds: 30
  auth:
    type: hmac
    secretRef: ocr-processor-v1

access:
  execute: CURATOR

locking:
  mode: PAGES

inputs:
  images:
    level: required
  xml:
    level: optional
    requiredForTargets:
      - REGION

outputs:
  xml:
    enabled: true
    mode: upsert
  images:
    enabled: false
  files:
    enabled: false

concurrency:
  maxActiveRuns: 1
  scope: PROJECT

runtime:
  model:
    name: default
    optional: true

parameters:
  threshold:
    type: number
    default: 0.5
    min: 0
    max: 1
    description: Minimum recognition confidence.
```

Replace `secretRef` with a configured endpoint secret before saving the definition.

## Top-Level Fields

| Field | Required | Default | Validation |
| --- | --- | --- | --- |
| `version` | Yes | none | Must be `1`. |
| `id` | Yes | none | `[a-zA-Z0-9][a-zA-Z0-9._-]{1,126}` and unique. |
| `name` | Yes | none | Non-blank text. |
| `description` | No | none | Text shown in the UI. |
| `category` | No | `WORKFLOW` | `WORKFLOW`, `OCR_HTR`, `LAYOUT`, or `POSTPROCESSING`. |
| `targets` | No | `[PAGE]` | One or more of `PAGE`, `REGION`, `TEXT_LINE`. Duplicate values are ignored. |
| `endpoint` | Yes | none | Endpoint object. |
| `access` | No | `CURATOR` | Execution role object. |
| `locking` | No | `PAGES` | Locking object. |
| `inputs` | Yes | none | At least one input type must be enabled. |
| `outputs` | Yes | none | At least one output type must be enabled. |
| `concurrency` | No | one active run per project | Concurrency object. |
| `runtime` | No | none | Metadata currently parsed and stored. |
| `parameters` | No | `{}` | Parameter definitions. |

## Endpoint

```yaml
endpoint:
  url: https://processor.example.org/dispatch
  healthUrl: https://processor.example.org/health
  preflightUrl: https://processor.example.org/preflight
  timeoutSeconds: 30
  auth:
    type: hmac
    secretRef: processor-v1
```

| Field | Required | Default | Validation |
| --- | --- | --- | --- |
| `endpoint.url` | Yes | none | HTTP/HTTPS URL, host required, no credentials, no fragment. |
| `endpoint.healthUrl` | No | none | Same URL validation as `endpoint.url`. |
| `endpoint.preflightUrl` | No | none | Signed `POST` endpoint used by **Test endpoint** to verify HMAC auth, processor identity, protocol version, and required capabilities. |
| `endpoint.timeoutSeconds` | No | `30` | Integer `1..300`. |
| `endpoint.auth.type` | No | `none` | `none` or `hmac`. External endpoints must use `hmac`. |
| `endpoint.auth.secretRef` | For HMAC | none | Must match the endpoint-secret reference pattern and resolve to a configured secret. |

Endpoint policy:

- Configure `preflightUrl` for SDK-based processors. LAREX signs the preflight
  exactly like a dispatch and validates the structured response. When it is
  omitted, **Test endpoint** falls back to the unauthenticated `healthUrl` (or a
  `HEAD` request to `url`), which proves reachability only.

- External endpoints must use HTTPS.
- Local/private endpoints may use HTTP when insecure local endpoints are allowed.
- If `LAREX_ACTIONS_ENDPOINT_ALLOWED_ORIGINS` is configured, the endpoint origin must be listed.
- URLs must not contain username/password credentials or fragments.

## Access

```yaml
access:
  execute: CURATOR
```

| Value | Meaning |
| --- | --- |
| `EDITOR` | Any workspace member can run the Action. |
| `CURATOR` | Only users who can manage projects in the workspace can run it. |

Default is `CURATOR`.

## Locking

```yaml
locking:
  mode: PAGES
```

| Value | Meaning |
| --- | --- |
| `PAGES` | Lock only affected pages. |
| `PROJECT` | Lock the entire project. |

Default is `PAGES`.

## Inputs

```yaml
inputs:
  images:
    level: required
  xml:
    level: optional
    requiredForTargets:
      - REGION
```

At least one input type must be enabled.

| Level | Meaning |
| --- | --- |
| `none` | Do not expose this input for the selected target. |
| `optional` | Expose the input when available; missing data does not exclude a page. |
| `required` | Exclude pages that do not provide this input. |

`requiredForTargets` overrides the base level to `required` for the listed targets. Each target must also appear in the top-level `targets` list. This supports processors that can create PAGE XML for a full page but need existing XML geometry for region-scoped processing.

Legacy booleans remain supported: `true` maps to `optional`, while `false` maps to `none`. New definitions should use explicit levels so the run dialog can show accurate compatibility messages.

When image input is active for the selected target, users can choose global or per-page image variants at run time. LAREX sends the resolved levels in dispatch and pull-input payloads as `inputRequirements`.

## Outputs

```yaml
outputs:
  xml:
    enabled: true
    mode: upsert
  images:
    enabled: true
    variant: action-copy
    mode: upsert
  files:
    enabled: true
```

At least one output type must be enabled.

| Field | Required when enabled | Default | Validation |
| --- | --- | --- | --- |
| `outputs.xml.enabled` | No | `false` | Boolean. |
| `outputs.xml.mode` | No | `upsert` | `upsert` or `append`. |
| `outputs.images.enabled` | No | `false` | Boolean. |
| `outputs.images.variant` | Yes for image output | none | `[a-zA-Z0-9][a-zA-Z0-9._-]{0,63}`. |
| `outputs.images.mode` | No | `upsert` | `upsert` or `append`. |
| `outputs.files.enabled` | No | `false` | Boolean. Enables arbitrary durable files in the project Outputs panel. |

Result uploads are still validated against the processor declaration. A processor cannot upload XML, images, or custom files unless the corresponding output is enabled. Custom outputs are a flat file collection in version 1; archive directory-shaped results before returning them.

## Concurrency

```yaml
concurrency:
  maxActiveRuns: 1
  scope: PROJECT
```

| Field | Default | Validation |
| --- | --- | --- |
| `maxActiveRuns` | `1` | Integer `1..100`. |
| `scope` | `PROJECT` | `PROJECT`, `WORKSPACE`, or `GLOBAL`. |

Concurrency counts active runs for the same Action definition.

## Runtime Metadata

```yaml
runtime:
  model:
    name: default
    optional: true
```

`runtime.model.name` and `runtime.model.optional` are parsed and stored as metadata. They can document the expected model or tell admins that model configuration is optional, but current run parameter resolution is based on `parameters`.

## Parameters

```yaml
parameters:
  threshold:
    type: number
    default: 0.5
    min: 0
    max: 1
    description: Minimum confidence.
    required: false
```

| Field | Default | Validation |
| --- | --- | --- |
| Parameter name | none | `[a-zA-Z0-9][a-zA-Z0-9._-]{0,63}`. |
| `type` | `string` | `string`, `number`, `integer`, or `boolean`. |
| `default` | Type default | Must match type and numeric range. |
| `min` | none | Numeric lower bound. |
| `max` | none | Numeric upper bound; must be >= `min`. |
| `description` | none | Help text. |
| `required` | none | Parsed as metadata. |

Default runtime values:

| Type | Default when `default` is omitted |
| --- | --- |
| `string` | empty string |
| `number` | `0.0` |
| `integer` | `0` |
| `boolean` | `false` |

The run dialog initializes parameters from these defaults. Users can adjust them for an individual run, and LAREX validates submitted values against the declared type and numeric range before dispatch.

## Validation Messages

Common validation failures:

| Path | Cause |
| --- | --- |
| `version` | Missing or not `1`. |
| `id` | Invalid format or duplicate processor ID. |
| `endpoint.url` | Missing, invalid, non-HTTP(S), contains credentials/fragment, or violates origin/HTTPS policy. |
| `endpoint.auth` | External endpoint configured without HMAC. |
| `endpoint.auth.secretRef` | Missing, invalid, or no matching secret is configured. |
| `inputs` | Neither images nor XML enabled. |
| `outputs` | Neither image nor XML output enabled. |
| `outputs.*.mode` | Not `upsert` or `append`. |
| `concurrency.maxActiveRuns` | Outside `1..100`. |
| `parameters.*.default` | Does not match type or numeric range. |
