# Examples

These examples show common Action patterns. Replace endpoint URLs and `secretRef` values with values from your deployment.

## Development Mock Processor

The repository includes a mock processor in `scripts/mock-processor`. It uses `larex-action-sdk`, exposes a FastAPI app, downloads selected input, sends heartbeats, and uploads copied image/XML results.

Local definition:

```yaml
version: 1
id: mock-image-copy
name: Mock Image Copy
description: Development processor that copies the first page image and XML back as Action outputs.
category: WORKFLOW
targets:
  - PAGE
  - REGION
  - TEXT_LINE

endpoint:
  url: http://mock-action-processor:9000/dispatch
  healthUrl: http://mock-action-processor:9000/health
  preflightUrl: http://mock-action-processor:9000/preflight
  timeoutSeconds: 30
  auth:
    type: hmac
    secretRef: mock-processor-v1

access:
  execute: CURATOR

locking:
  mode: PAGES

inputs:
  images:
    level: optional
  xml:
    level: optional

outputs:
  xml:
    enabled: true
    mode: upsert
  images:
    enabled: true
    variant: action-copy
    mode: upsert
  files:
    enabled: true

concurrency:
  maxActiveRuns: 1
  scope: PROJECT

runtime:
  model:
    name: mock
    optional: true

parameters:
  threshold:
    type: number
    default: 0.5
    min: 0
    max: 1
```

Local environment:

```yaml
app:
  environment:
    LAREX_ACTION_ENDPOINT_SECRET_MOCK_PROCESSOR_V1: dev-mock-action-secret-change-me

mock-action-processor:
  environment:
    LAREX_DISPATCH_HMAC_SECRET: dev-mock-action-secret-change-me
    LAREX_OUTPUT_IMAGE_VARIANT: action-copy
```

Use it to test:

- endpoint secret resolution
- signed dispatch
- callback public base URL
- heartbeat progress
- cancellation
- image result import
- XML result import
- scoped region/textline imports

## Minimal OCR/HTR Processor Definition

```yaml
version: 1
id: htr-lines
name: HTR Lines
description: Recognize selected textlines and return updated PAGE XML.
category: OCR_HTR
targets:
  - TEXT_LINE

endpoint:
  url: https://htr.example.org/dispatch
  healthUrl: https://htr.example.org/health
  preflightUrl: https://htr.example.org/preflight
  timeoutSeconds: 120
  auth:
    type: hmac
    secretRef: htr-lines-v1

access:
  execute: CURATOR

locking:
  mode: PAGES

inputs:
  images:
    level: required
  xml:
    level: required

outputs:
  xml:
    enabled: true
    mode: upsert

concurrency:
  maxActiveRuns: 2
  scope: WORKSPACE

parameters:
  confidenceThreshold:
    type: number
    default: 0.5
    min: 0
    max: 1
    description: Minimum confidence for accepted textline output.
```

Processor behavior:

1. Pull input.
2. Read `targetSelection.pages[].textLineIds`.
3. Download the page image and PAGE XML.
4. Resolve textline geometry from PAGE XML.
5. Run recognition for selected lines.
6. Return normal PAGE XML for the page.
7. Let LAREX import only selected textlines.

## Minimal FastAPI Processor Skeleton

```python
import os

from larex_actions import ActionCancelled, ActionContext
from larex_actions.fastapi import create_larex_action_app


async def process(ctx: ActionContext) -> None:
    try:
        action_input = await ctx.pull_input()
        total = max(len(action_input.pages), 1)
        for index, page in enumerate(action_input.pages, start=1):
            await ctx.heartbeat(
                progress_percent=int((index - 1) / total * 100),
                status_message=f"Processing {page.name}",
                raise_on_cancel=True,
            )

            # Replace this block with OCR/layout/model work.
            results = ctx.result_builder()
            if page.xml:
                xml_bytes = await ctx.download_bytes(page.xml[0])
                results.add_xml_bytes(
                    page_id=page.id,
                    content=xml_bytes,
                    file_name=f"{page.name}-processed.xml",
                )
            await ctx.submit_page_results(page.id, results, f"Imported {page.name}")

        await ctx.complete(message="Processing complete")
    except ActionCancelled:
        raise


app = create_larex_action_app(
    processor_id=os.getenv("LAREX_PROCESSOR_ID", "htr-lines"),
    dispatch_secret=os.environ["LAREX_DISPATCH_HMAC_SECRET"],
    handler=process,
)
```

## Postprocessing To A Durable File

Use `POSTPROCESSING` when the primary result is a custom export or downstream analysis artifact:

```yaml
version: 1
id: page-ner-export
name: PAGE NER Export
category: POSTPROCESSING
targets: [PAGE]
endpoint:
  url: https://processors.example.org/ner/dispatch
  healthUrl: https://processors.example.org/ner/health
  preflightUrl: https://processors.example.org/ner/preflight
  auth:
    type: hmac
    secretRef: ner-v1
inputs:
  images:
    level: none
  xml:
    level: required
outputs:
  files:
    enabled: true
```

With an SDK release that supports custom files, a processor can convert the PAGE XML, run NER, and return a project-level JSONL result:

```python
if not ctx.capabilities.custom_file_results:
    raise RuntimeError("This LAREX server does not support custom file results")

results = ctx.result_builder()
results.add_file_bytes(
    content=ner_jsonl,
    file_name="named-entities.jsonl",
    mime_type="application/x-ndjson",
)
await ctx.complete(results, "NER export complete")
```

The completed run creates one entry in the project's **Outputs** panel. Return archives when the output needs a directory structure.

## Kraken Segmentation Processor

The [`OCR4all/larex-action-kraken`](https://github.com/OCR4all/larex-action-kraken) processor runs Kraken-based PAGE XML layout segmentation workflows. It supports PAGE-targeted baseline segmentation, REGION-targeted segmentation for selected text regions, HMAC verification through the SDK, and result upload through the LAREX callback API.

Core setup:

1. Deploy `ghcr.io/ocr4all/larex-action-kraken:0.4.0` or build the repository Dockerfile.
2. Create an endpoint secret in LAREX, for example `kraken-segmentation-v1`.
3. Set the revealed secret in the processor as `LAREX_DISPATCH_HMAC_SECRET`.
4. Register the Action definition from the processor repository and update endpoint URLs.
5. Test `/health`.
6. Assign the Action to a workspace/project.

Important environment variables:

| Variable | Default | Purpose |
| --- | --- | --- |
| `LAREX_DISPATCH_HMAC_SECRET` | required | Shared dispatch HMAC secret generated by LAREX. |
| `LAREX_PROCESSOR_ID` | `kraken-segmentation` | Processor ID expected in dispatch headers. |
| `LAREX_ALLOWED_CALLBACK_ORIGINS` | SDK default | Accepted LAREX callback origins. |
| `LAREX_ACTION_ROUTE_PREFIXES` | empty | Preserved reverse-proxy prefixes for dispatch/health. |
| `KRAKEN_DEVICE` | `cpu` | Kraken device, for example `cpu`, `cuda`, or `mps`. |
| `KRAKEN_PRECISION` | `32-true` | Kraken precision argument. |
| `KRAKEN_TEXT_DIRECTION` | `horizontal-lr` | Text direction for segmentation. |
| `KRAKEN_SEGMENTATION_MODEL` | empty | Optional Kraken model path/name. |
| `KRAKEN_MAX_PROCESS_SECONDS` | `900` | Per-page subprocess timeout. |

Path-prefix example:

```bash
LAREX_ACTION_ROUTE_PREFIXES=/kraken
```

```yaml
endpoint:
  url: https://processors.example.org/kraken/dispatch
  healthUrl: https://processors.example.org/kraken/health
  preflightUrl: https://processors.example.org/kraken/preflight
  auth:
    type: hmac
    secretRef: kraken-segmentation-v1
```

The reverse proxy must preserve `/kraken` when forwarding to the container.
