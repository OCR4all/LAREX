# Dataset Model Evaluation

Evaluation Actions receive a frozen image/PAGE XML pair for every selected
dataset item and return one structured report. They use the normal Action
dispatch, HMAC authentication, queue, heartbeat, cancellation, and realtime
status flow, but create no page locks and upload no files.

```yaml
version: 1
id: example-ocr-evaluation
name: OCR recognition evaluation
kind: EVALUATION
category: OCR_HTR
targets: [PAGE]
locking:
  mode: NONE
inputs:
  images:
    level: required
  xml:
    level: required
evaluation:
  profile: larex.ocr-recognition
  profileVersion: 1
  splits:
    TRAIN: none
    VAL: optional
    TEST: required
```

The profile and profile version define the comparable metric vocabulary. The
initial profiles are `larex.ocr-recognition` (CER/WER, scripts, confusions and
line samples) and `larex.layout-segmentation` (pixel accuracy/IoU, baseline
metrics, class diagnostics and page samples). Custom Actions may publish their
own namespaced profiles.

Completed callbacks must contain exactly one `evaluationReport` in the
multipart manifest. Reports contain finite summary metrics plus optional
searchable tables and samples. LAREX validates profile/version, unique keys and
sample IDs, input references, JSON values, and a 10 MiB serialized size limit
before storing the report with the run history.

## Report field reference

The JSON names below are the wire format used in `evaluationReport`. Use the
SDK models in `larex-action-sdk>=0.15.0,<0.16` to construct and submit reports.
"Default" describes what the SDK supplies when you omit a field; required fields
must be provided. Python models accept both these JSON names and their snake-case
attribute names, for example `profileVersion` / `profile_version` and
`inputId` / `input_id`.

### EvaluationReport

| Field | Type | Required / default | Meaning and constraints |
| --- | --- | --- | --- |
| `schemaVersion` | integer | Default: `1` | Report schema version. Only `1` is supported. Include it when submitting JSON directly. |
| `profile` | string | Required | Nonblank metric vocabulary identifier, such as `larex.ocr-recognition` or `larex.layout-segmentation`. Must exactly match `evaluation.profile` in the Action YAML. |
| `profileVersion` | integer | Required | Positive version of that vocabulary. Must exactly match `evaluation.profileVersion` in the Action YAML. |
| `title` | string | Required | Nonblank human-readable report title. |
| `summary` | array of `EvaluationMetric` | Required, nonempty | Aggregate metrics for the run. Metric keys must be unique within this array. Matching keys are used for baseline comparisons. |
| `tables` | array of `EvaluationTable` | Default: `[]` | Searchable diagnostic tables. Table keys must be unique within the report. |
| `samples` | array of `EvaluationSample` | Default: `[]` | Per-input or per-target diagnostics. Sample IDs must be unique within the report. |
| `warnings` | array of strings | Default: `[]` | Human-readable caveats, such as skipped inputs or incomplete diagnostics. |
| `metadata` | JSON object | Default: `{}` | Processor-defined provenance, such as model identifier, engine version, or evaluation settings. |

Keep metric keys and their meanings stable within a profile/version. The profile
is a compatibility identifier; selecting an OCR profile does not automatically
calculate CER/WER or require a fixed set of metric keys. The processor calculates
and supplies the metrics. Change the profile version when their meaning changes.

### EvaluationMetric

Use the same object shape for report `summary` and sample `metrics`.

| Field | Type | Required / default | Meaning and constraints |
| --- | --- | --- | --- |
| `key` | string | Required | Stable, nonblank machine-readable identifier, for example `cer` or `mean_iou`. The SDK trims whitespace and limits it to 256 characters. |
| `label` | string | Required | Nonblank display label. The SDK trims whitespace and limits it to 256 characters. |
| `value` | number | Required | Finite integer or float. Numeric strings, booleans, `NaN`, and infinity are not valid metric values. |
| `format` | string enum | Default: `NUMBER` | `NUMBER`, `INTEGER`, or `PERCENT`. This controls presentation; use integer values for counts. |
| `unit` | string or null | Default: `null` | Optional display unit, such as `ms` or `characters`. |
| `direction` | string enum | Default: `NEUTRAL` | `HIGHER_IS_BETTER`, `LOWER_IS_BETTER`, or `NEUTRAL`. Controls whether an increase/decrease is shown as an improvement in baseline comparisons. |

`PERCENT` values are fractions: `0.12` displays as **12%**, not 0.12%.
Percent deltas are displayed in percentage points. For CER/WER use
`LOWER_IS_BETTER`; for accuracy/IoU use `HIGHER_IS_BETTER`.

### EvaluationTable

| Field | Type | Required / default | Meaning and constraints |
| --- | --- | --- | --- |
| `key` | string | Required | Nonblank table identifier, unique within the report. |
| `title` | string | Required | Nonblank display title. |
| `columns` | array of `EvaluationTableColumn` | Default: `[]` | Displayed columns, in order. Column keys must be unique within the table. |
| `rows` | array of `EvaluationTableRow` | Default: `[]` | Serialized diagnostic rows. Every row uses the `values` wrapper described below. |
| `truncated` | boolean | Default: `false` | Set to `true` when the report contains only a subset of the full diagnostic rows. |
| `totalRows` | integer | Default: number of serialized rows | Total number of rows before truncation. Must be nonnegative and at least `len(rows)`. The SDK infers `len(rows)` if omitted or set to `0`; explicitly set the full count for truncated tables. |

### EvaluationTableColumn

| Field | Type | Required / default | Meaning and constraints |
| --- | --- | --- | --- |
| `key` | string | Required | Nonblank key used to look up cells in each row's `values` object. The SDK trims whitespace and limits it to 256 characters. |
| `label` | string | Required | Nonblank display label. The SDK trims whitespace and limits it to 256 characters. |
| `type` | string enum | Default: `STRING` | `STRING`, `NUMBER`, `INTEGER`, or `BOOLEAN`. Describes the intended cell type. Supply JSON values consistent with it; cell types are not coerced or enforced against column declarations. |

### EvaluationTableRow

| Field | Type | Required / default | Meaning and constraints |
| --- | --- | --- | --- |
| `values` | JSON object | Default: `{}` | Maps column keys to cell values. Use `{"values": {"reference": "e", "count": 42}}`, not an unwrapped cell map. |

Use column keys for cells intended for display. Arbitrary valid JSON can be stored
in a cell, but primitive strings, numbers, booleans, or null are the intended
values for the declared column types.

### EvaluationSample

| Field | Type | Required / default | Meaning and constraints |
| --- | --- | --- | --- |
| `id` | string | Required | Nonblank identifier, unique within the report. Use a stable value such as `item-1:line-1` when emitting multiple samples per input. |
| `inputId` | string | Required | Dataset item ID from `action_input.pages[i].id`. Must refer to an input in this run. Do not use `sourcePageId` here. |
| `targetId` | string or null | Default: `null` | Optional region or text-line identifier from the input PAGE XML. Useful for locating the evaluated target; LAREX does not validate this identifier against XML contents. |
| `label` | string or null | Default: `null` | Optional human-readable sample label. |
| `status` | string enum | Default: `OK` | `OK`, `SKIPPED`, or `FAILED`. Describes this sample, independently of the run's completion status. |
| `fields` | JSON object | Default: `{}` | Processor-defined diagnostics, such as reference/prediction text or skip reasons. |
| `metrics` | array of `EvaluationMetric` | Default: `[]` | Sample-specific metrics using the same shape as summary metrics. These are diagnostic data, not aggregate baseline comparisons. |

### Validation and size limits

The report must be JSON-serializable and no larger than **10 MiB** after UTF-8
serialization. All nested object keys must be nonblank strings and all numbers
must be finite, including numbers inside cells, sample fields, and metadata.
Use JSON primitives, arrays, and objects; encode other Python values yourself.

The SDK validates report structure and revalidates it before result serialization.
LAREX additionally validates the configured profile/version and sample input
references. Invalid reports are rejected by the result callback. Keep large
sample collections and diagnostic tables within the report limit, using
`truncated` and `totalRows` when sending only a table subset.

## Complete JSON example

This is the report object itself, nested under `evaluationReport` in the result
manifest. `item-1` must be an actual dataset item ID from the current run.

```json
{
  "schemaVersion": 1,
  "profile": "larex.ocr-recognition",
  "profileVersion": 1,
  "title": "OCR recognition evaluation",
  "summary": [
    {
      "key": "cer",
      "label": "Character error rate",
      "value": 0.12,
      "format": "PERCENT",
      "direction": "LOWER_IS_BETTER"
    }
  ],
  "tables": [
    {
      "key": "confusions",
      "title": "Character confusions",
      "columns": [
        {"key": "reference", "label": "Reference", "type": "STRING"},
        {"key": "prediction", "label": "Prediction", "type": "STRING"},
        {"key": "count", "label": "Count", "type": "INTEGER"}
      ],
      "rows": [
        {"values": {"reference": "e", "prediction": "c", "count": 42}}
      ],
      "totalRows": 1,
      "truncated": false
    }
  ],
  "samples": [
    {
      "id": "item-1:line-1",
      "inputId": "item-1",
      "targetId": "line-1",
      "label": "Page 1 / line 1",
      "status": "OK",
      "fields": {"reference": "Hello", "prediction": "He11o"},
      "metrics": [
        {"key": "cer", "label": "Line CER", "value": 0.4, "format": "PERCENT", "direction": "LOWER_IS_BETTER"}
      ]
    }
  ],
  "warnings": [],
  "metadata": {"engine": "my-ocr", "model": "model-v1"}
}
```

## Submit with SDK 0.15

Install `larex-action-sdk[fastapi]>=0.15.0,<0.16`. An evaluation processor must
advertise `evaluationReports: true` during preflight. The default FastAPI
capabilities do not enable evaluation reports, so set them explicitly:

```python
import os

from larex_actions import ActionContext, EvaluationMetric, EvaluationReport
from larex_actions.fastapi import create_larex_action_app


async def evaluate(ctx: ActionContext) -> None:
    action_input = await ctx.pull_input()
    if action_input.kind != "EVALUATION":
        raise ValueError("This processor only accepts EVALUATION runs")

    # Download frozen image/XML pairs, then calculate your metrics.
    # This value is an example fixture; replace it with your measured CER.
    cer = 0.12
    await ctx.check_cancelled()
    report = EvaluationReport(
        profile="larex.ocr-recognition",
        profile_version=1,
        title="OCR recognition evaluation",
        summary=[EvaluationMetric(
            key="cer",
            label="Character error rate",
            value=cer,
            format="PERCENT",
            direction="LOWER_IS_BETTER",
        )],
    )
    await ctx.complete_evaluation(report, message="Evaluation complete")


app = create_larex_action_app(
    processor_id="example-ocr-evaluation",
    dispatch_secret=os.environ["LAREX_DISPATCH_HMAC_SECRET"],
    handler=evaluate,
    processor_capabilities={"evaluationReports": True},
)
```

You can also parse a report-shaped dictionary with
`EvaluationReport.model_validate(report_dict)` or construct its nested objects
with `EvaluationTable`, `EvaluationTableColumn`, `EvaluationTableRow`, and
`EvaluationSample`. For sample input references, always use `page.id` from the
pulled input.

`ctx.complete_evaluation()` submits a completed multipart manifest with exactly
one `evaluationReport` and an empty `files` list. The SDK handles serialization,
authentication, retries, and cooperative cancellation. The server must advertise
`capabilities.evaluationReports` in its dispatch or pulled input; otherwise the
SDK raises `EvaluationReportsUnsupported`. Do not use `ctx.complete()` to finish
an evaluation or upload the report as a custom result file. Report progress via
heartbeats and use `ctx.fail()` to report a failed run.

For framework-neutral processors, the equivalent submission method is
`ActionClient.complete_evaluation()`. The working mock implementations are in
`scripts/mock-processor/main.py` in the LAREX repository.

## Baseline comparisons

Baselines are offered only when the run has completed against the same dataset
and frozen-input fingerprint and uses the same report schema/profile/version.
Matching summary metrics are compared using their declared direction; percent
deltas are shown as percentage points. Tables and samples remain side-by-side
data without cross-profile calculations.

## Development mock processors

The development mock service exposes `mock-ocr-evaluation` and
`mock-layout-evaluation` from the same container as processing and training.
Both validate frozen pairs, wait for `delaySeconds`, and return deterministic
reports whose values can be varied with the `quality` parameter.
