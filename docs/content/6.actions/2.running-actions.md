# Running Actions

Users run Actions from LAREX, but processors execute outside the main app. The run dialog brings the two sides together: it lets users choose the processor, scope, image inputs, and target, then shows status until results are imported.

For the shorter everyday guide, see [Running LAREX Actions](/user-guide/larex-actions).

## Prerequisites

An Action appears only when all of these are true:

- the definition is enabled
- the Action is available to the workspace/project
- the Action supports the requested target
- the user has the required workspace role
- the project is not locked
- required input data exists for the selected scope

Unavailable Actions may still be listed with a blocked reason, such as curator access required or project locked.

## Project Scope Runs

From a project page, Actions can run on all pages or selected pages.

Use **All pages** when:

- the processor should build or refresh a complete project state
- the Action has project/workspace concurrency and can run unattended
- pages are consistently prepared

Use **Selected pages** when:

- testing a processor
- reprocessing failed pages
- reviewing a subset
- avoiding unnecessary locks or processor cost

## Editor Target Runs

From the editor, use the Action wand or context menu to select a target.

| Target | Selection | Notes |
| --- | --- | --- |
| `PAGE` | Active page | Useful for full-page recognition, cleanup, or segmentation. |
| `REGION` | One or more selected regions | Processor receives full page files plus selected region IDs. |
| `TEXT_LINE` | One or more selected textlines | Processor receives full page files plus selected textline IDs. |

The editor prompts to save unsaved PAGE XML before dispatch. Processors never see unsaved editor state.

## Image Variant Selection

When `inputs.images: true`, the run dialog can choose image inputs.

| Option | Behavior |
| --- | --- |
| Global variant | Send the same variant name for every page where it exists. |
| Per-page variant | Choose variants page by page. |
| Fallback enabled | Use the first available image when the requested variant is missing. |
| Fallback disabled | Skip pages where the requested variant is missing. |

If every page is skipped because the requested image variant is unavailable, the run cannot provide useful input. Choose another variant or enable fallback.

## Parameters

Action definitions can declare parameters. Current run behavior resolves defaults from YAML and sends those values to the processor. Treat parameter defaults as part of the processor contract.

## Queues And Concurrency

Concurrency limits can apply per project, workspace, or globally. If a limit is reached, LAREX may offer to schedule the run.

Queued runs start automatically when:

- an active run finishes
- the queued run is still valid
- locks are available
- the Action remains enabled and assigned

## Cancellation

Cancellation behavior depends on run status:

| Status | Cancellation behavior |
| --- | --- |
| `QUEUED` or `PENDING` | LAREX can cancel before dispatch. |
| `DISPATCHING` | LAREX records cancellation and completes the transition as soon as possible. |
| `RUNNING` | Processor must observe heartbeat cancellation and stop cooperatively. |
| `IMPORTING_RESULTS` | Import may already be applying validated results. |

Processor authors should use SDK cancellation helpers. Users should not assume a running processor stops instantly.

## Retry

Retry is available for failed or cancelled runs. A retry creates a new run with the same:

- Action definition
- project/workspace scope
- target selection
- page IDs
- resolved parameters

Use retry after transient endpoint, model, GPU, or network failures. Do not retry until the underlying issue is fixed when validation or configuration caused the failure.

## History And Logs

Run history shows status, messages, progress, queue position, errors, and logs. Admin views provide broader workspace/project visibility and audit context.

Useful checks:

- Did dispatch reach the endpoint?
- Did the processor heartbeat?
- Did cancellation get acknowledged?
- Did result import fail because of XML, image, size, or scope validation?
- Did the run touch the pages currently open in the editor?
